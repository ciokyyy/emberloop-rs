# Ship an emberloop-rs change

Steps, in order:

1. Read the AGENTS.md chain for every crate you touch before editing. Write the failing test first, then fix.
2. Run focused tests while iterating (`cargo test -p <crate> --lib`; for UI changes `bun run test` and `bun run check` inside `web/` — this repo is bun-only, never npm or pnpm). If you touched anything under `web/src`, run `bun run build` in `web/` first: the nextest test `the_embedded_web_bundle_is_newer_than_its_sources` fails on a `web/build` older than the sources. Then run `scripts/check` with `background: true` and wait once. It must pass unchanged; never weaken it. Its `openapi` stage rewrites `openapi.json` and `web/src/lib/api/schema.d.ts`; the `generated` stage is a bare `git diff --exit-code` on those two paths, so it compares the working tree with the index and a fresh regeneration fails until the files are staged (`git add openapi.json web/src/lib/api/schema.d.ts`). Staging is enough; ask before committing.
3. Build the release with `EMBERLOOP_HOME=<data root> HOME=<real home> scripts/release`. Set both variables explicitly: a Session HOME can be a harness-private directory, and the default home lookup then fails.
4. Install with `target/release/emberloop-daemon --data-root <data root> update --file "$PWD/target/release/emberloop-daemon" --session <current session id>`. The command only queues the update: it prints `Update X -> Y is queued`, and the daemon installs and restarts once the session is idle. Do step 5 after that restart, not right after the command.
5. Verify: `readlink <data root>/current` names the new release, `emberloop-daemon --version` matches, and `curl localhost:3000/api/version` agrees. For a `web/` change, prove the code reached the served bundle before reporting success: grep `web/build` for a string or rule your change introduced (`grep -rl` over `_app/`; CSS rules live in `_app/immutable/assets/*.css`), `curl` that artifact from the daemon and compare its `md5sum` with the file in `web/build`, then measure the live page at `http://127.0.0.1:3000/...` with `agent-browser` rather than the dev server. Load the heaviest Session you have and step through three Session URLs of one project, asserting `document.querySelector('main').innerText.length > 0` after each: the update restart errors every open EventSource at once, which is exactly when a stale-stream bug surfaces. Check main text, not feed rows — a large Session shows no mounted rows for several seconds while the virtualizer fills. For an installable app, also check `navigator.serviceWorker.getRegistration('/')` in that page reports an `activated` worker whose scope is the origin root.
6. For a behavior change that reaches a live model, test it on a real Session. See `references/live-session-testing.md` for the endpoints, steer route check, and polling method.

Pitfalls:
- The bash tool refuses shell redirects (`> file`, `2>&1`). Run `scripts/check` and `scripts/release` with `background: true` and no redirect, then wait on the handle and read its log path.
- A daemon update restarts every Session process, so reviewer Sessions (`spawn` spec/standards) go inactive with no report. After the restart call `result` on each, then `steer` it with the same `ticketPath` and `startingPoint` to re-review; do not respawn.
- Do not kill the daemon by hand while any Session works; use the `update` command so the restart is orderly.
- Run `cargo fmt --all -- --check` first and list the `Diff in <file>` lines. Format only those files (`rustfmt --edition 2021 <file>`, matching the workspace edition), not the whole tree: `cargo fmt --all` reformats unrelated uncommitted files. Calling bare `rustfmt <file>` can fail in Rust 2015 mode. Keep `pub mod` lines alphabetical; rustfmt reorders them and fails `scripts/check`'s fmt stage otherwise.
- `scripts/check` launches each stage in the background and prints its verdict only at the end; one printed tail can hide green stages. Read `target/<stage>.log` and `target/*.failed` for the stages you care about. A cold first run can also break the total budget in `scripts/check-budget.tsv` while every stage passed (a cold compile is minutes); rerun warm and judge the budget line separately from stage results.
- Every harness start waits on a ready handshake: the ACP driver sends `(session_id, options, resumed)` to the waiter once `session/new` returns. An edit in that block that drops the send makes every harness start hang until the timeout (13 nextest timeouts plus one acceptance failure), while unit tests that never start a harness still pass. After editing harness start code, look for the timeout count before trusting a green focused test run.
- A new required prop on a Svelte component breaks every existing test mount with a type error in `svelte-check`. Give new props a default (`onskills = () => {}`) unless every caller must pass one.
- A new required field on a schema-generated type (`UsageRecord`, `Session`, …) breaks every fixture that builds one by hand, and `svelte-check` reports only the first. After regenerating `web/src/lib/api/schema.d.ts`, grep the type name across `web/src` (`grep -rln UsageRecord web/src`) and give each test helper the field; a defaulted parameter (`fold = false`) keeps the existing cases unchanged.
- Read the failing test's assertion before changing behavior: a test that pins the old behavior (e.g. a 409 for a feature being replaced) must be rewritten to the new contract, not left failing.
- A Session that started before the update has no frozen skill catalog (`<session>/skill-catalog.md` is written only when a Session starts). Say so; do not call it a bug.
- Clippy denies `tokio::time::sleep` in tests (`disallowed_methods`). Wait with a bounded `tokio::task::yield_now().await` loop; a live test that waits on a real model may `#![allow(clippy::disallowed_methods)]` for the file.
- To prove a proxy feature keeps the provider cache intact, run an `#[ignore]` live test (pattern: `crates/daemon/tests/review_live.rs`, `LIVE_CLAUDE_HOME`, `LIVE_CLAUDE_BIN`) and compare `(input, cached, created)` of the proxy `usage` events before and after the feature's side request. In an API test, call `state.models.refresh().await` before `PUT /api/settings`; without a catalogue the title-model check answers 400. A PUT now also writes `<data root>/settings.json`, so a test that changes settings leaves that file behind and a restart test loads it with a second `AppState` on the same data root.
- A new proxy event payload must keep the shape its web reader expects (e.g. `skill-review` `ops` is a flat op list, not the call's `{ops}` wrapper). Test the emitted event data, not only that the event fired.
- A change to `reset_history` semantics (history now carried across a reset) breaks tests that assert the old restart; rewrite those to the new contract. Same-role merges in `carry` are needed because several wires refuse two turns of one role in a row.
- Probing the agy ACP server (`agy_acp_server.par`) by hand: set `GEMINI_HOME` to `<config>/accounts/agy/default`, not `accounts/agy`, or it answers `Authentication required`. `session/new` makes three sequential Google calls (token refresh, loadCodeAssist, fetchAvailableModels) and can take 20s+ on a slow-DNS host; `crates/harness-acp/src/lib.rs` waits 60s (`SESSION_READY_TIMEOUT`) for session creation. Check `curl -w %{time_namelookup}` before blaming auth.
- The daemon's tracing must write to stderr: the `mcp` subcommand (spawned by agy/claude/pi harnesses, inheriting `RUST_LOG`) speaks JSON-RPC on stdout, and a log line there breaks the harness's `tools/list`. Test with `crates/daemon/tests/mcp_stdout.rs`.
- Google (agy) streams repeat `usageMetadata` per chunk and early readings lack `cachedContentTokenCount`; the proxy holds the newest reading and publishes once at stream end (`SseState::held`). Two usage events per step, cached 0 then ~90%, mean a metering regression, not a cache invalidation. A one-off red that repeats green is load flake: `background_loads_the_runtime_env_file_too` and `harness-pi::pi the_session_home_points_pi_at_the_proxy_and_the_tools` both spawn a binary. Confirm with `cargo nextest run --workspace` before investigating.
- `git stash` on one file in a dirty tree is unsafe for a red/green check; prove red by reasoning or a temporary edit instead.
- nextest's default `slow-timeout = { period = "4s", terminate-after = 1 }` kills a test that spawns a binary under load: it FAILs in a fraction of a second with no captured output, then passes alone. Do not rerun until green. `.config/nextest.toml` overrides `filter = "binary(pi)"` with `threads-required = "num-cpus"` and a 20s period, because that binary also sets a process environment variable and racing tests in it share it.
- `scripts/check` prints `budget exceeded: <stage> <ms> > <budget>` in its closing table even when every stage passed. The web stage re-runs in full whenever any `web/src` file changed, so an overrun there is a measured fact, not a flake: time its sub-commands (`svelte-check`, `fallow`, `vitest`, `vite build`) before calling the host slow. Vitest's default forked pool re-paid the Svelte compile per worker file, which put the stage at 224 s against a 180 s budget; `pool: "threads"` in `web/vite.config.ts` brought it to 163 s. Never raise the budget to make a change pass.
- Svelte/Tailwind work in `web/`: load the `emberloop-rs-web-ui` skill for the token list, mobile layout habits and jsdom stubs.
- Another agent may be working in the same checkout. Read `git diff -- <file>` for every file you changed before staging: a file where you only edited a doc comment can carry their code hunks. Stage your own hunks only, or leave the change uncommitted and tell the user which files are yours. Never `git add -A` in a shared tree. Recipe for separating the hunks: `references/shared-tree-commits.md`.
- A checkpoint commit of a mixed checkout is several commits, one area each, staged by explicit path: `crates/api`+`crates/daemon`+`crates/tools` with the generated `openapi.json` and `schema.d.ts`, then `crates/proxy`, then `web/src` with `design.md`/`design.figcraft`, then the `.agents` skills. Run `scripts/check` before committing, since its `generated` stage compares the index and needs the generated pair staged anyway, and confirm the set with `git diff --cached --stat` (`git status` has no `--cached` flag). Name a changed user-visible default in the body (`max_context_limit` 75 to 20, `emergency_threshold_percent` 95 to 25): a default buried in a diff is invisible to whoever reads the log. Put the agent byproducts in `.gitignore` first (`/.tmp`, `/.scratch`, `/.claude`, `.agents/skills/.backup`, `.agents/skills/.locks`), or the checkpoint's `git add -A <dir>` sweeps tool output and skill backups into the tree.
- Adding a harness tool, a prompt id or an API route touches a long fixed list of files (pinned test lists, three daemon config builders, the review whitelist, generated OpenAPI). Walk `references/new-harness-tool.md` before the first edit.
- Changing a tool's model-facing behaviour reaches four places before it is done: the code, `crates/prompts/prompts/tool.<name>.md`, the inline input schema in `crates/tools/src/mcp.rs`, and that crate's `AGENTS.md` bullet. `crates/tools/tests/contract.rs` polices the wording: every backticked word must be a parameter, value or tool name (`bash: `rtk` is not a parameter, value or tool`), and the read path description must keep naming each accepted form (directory, URL, `ctx:<handle>`), so write an external binary or suffix plain. Run `cargo test -p tools` before `scripts/check` to see those contract failures in seconds. Porting behaviour from the Go Emberloop copies its guards and fallbacks exactly, including a test that skips when an external binary is missing.
- A hashline `PUT N.=M` replaces its whole range. When the replacement ends a block, include the closing `}` and any attribute line above the first replaced line (`#[derive(...)]`), and re-read the result: a dropped `}` or derive costs a compile cycle. Insert new lines with `PUT >N:`; use `PUT N.=N:` only when the body is exactly one line, or the leftover tail is dropped/duplicated and the old line above a block (`pub mod x;`, `} = $props();`, `#[utoipa::path(`) is left orphaned.
- Model-facing text has two prices. A tool description, `policy`, or `compress` loads on every request of every Session; a nudge loads only when it fires. Put new wording where it is read at the moment it changes behaviour, and keep the always-resident files short.
- A Session that idles or will not resume, and a provider that 401s in one agent while working in another, is often account state rather than a bug: check the usage limit and the per-Session credential before reading daemon code. Recipe in `references/provider-auth-and-quota.md`.
- Never assume a fold or review feature works live from unit tests alone. State what was not checked in the final reply.
- Built-in MCP subsystems: do not leave core tools as optional user entries. Use daemon-level `ensure` on `<config root>/mcp.json`, auto-inject session project context in `crates/tools/src/mcpclient.rs`, and keep project-scoped views in a header `•••` right drawer rather than the global sidebar (see `references/baked-in-subsystems.md`).
- Web check health score (`bunx fallow health --score --min-score 87.9`): dead code deductions drop the score below 88. Keep unconsumed helpers private (no `export`), delete or consume unreferenced files, and split complex Svelte views into subcomponents to stay under cognitive complexity limits. The floor is only 0.1 under a healthy tree, so measure the baseline's penalty lines in a throwaway worktree before refactoring anything large: the `unit size` deduction is usually pre-existing debt, not yours (recipe in the `emberloop-rs-web-ui` skill).
- CI steps have an order the tests enforce: any step that regenerates a tracked web source (`bun run generate:api` writes `web/src/lib/api/schema.d.ts`) must run before the Web bundle step, and `bun install --frozen-lockfile` must run before it, or the step exits 127 (`openapi-typescript: command not found`) or `the_embedded_web_bundle_is_newer_than_its_sources` fails after a green build.
- `pi-ai` is a git pin to the `ciokyyy/pi-rust` fork, not a crates.io release. Before reporting a dependency update, check the upstream `yannelli/pi-rust` tag and rebuild the fork patch on it; recipe in `references/pi-ai-pin.md`.
- `git push` here has no stored https credential and fails with a credential prompt. Push with `git -c credential.helper='!gh auth git-credential' push origin master`.
- When the checkout carries another agent's uncommitted work, document committed behaviour only: read the file at `git show HEAD:<path>`, not the working tree, so a WIP default does not end up in the docs.
- A docs change with Mermaid diagrams is not done until each block renders: `bunx -p @mermaid-js/mermaid-cli@11 mmdc -p puppeteer.json -i d.mmd -o d.svg` with `puppeteer.json` holding `{"args":["--no-sandbox","--disable-setuid-sandbox"]}` (headless Chrome refuses to start as root without it).
- Compiling external dependencies or binaries: `/tmp` can be a small tmpfs (e.g. 5GB at 95% full), causing `collect2: fatal error: ld terminated with signal 7 [Bus error]`. Set `CARGO_TARGET_DIR` on a physical disk partition with sufficient headroom before building.
