# Adding a harness tool or a prompt id

A new tool or prompt id touches many places. Miss one and a pinned test or a live Session fails.

1. Prompt id: add the const, the `PROMPT_IDS` entry and the `default_text` arm in `crates/prompts/src/lib.rs`; add the `include_str!` const in `defaults.rs`; add the `prompts/<id>.md` file. A tool's id is `tool.<name>.description`.
2. Prompt text is validated for placeholders when the store loads. A literal double-brace token in a default file (even as an example) is an `UnknownPlaceholder` and fails every pin test. Describe placeholders in words.
3. Tool: add `crates/tools/src/<name>.rs`, `pub mod` (alphabetical), the dispatch arm in `crates/tools/src/lib.rs`, the spec in `tool_specs` in `mcp.rs`, and the `_SPECS` entry in `crates/tools/src/execute.rs`. A schema `required` list holds only what every call needs. Only `_SPECS` tools get Python `tools.<name>(...)` attributes inside `execute`; Session-conditional tools (`spawn`, `steer`, `stop`, `result`, `submit`) and dynamic MCP tools must be called via `tools.call("<name>", ...)` inside scripts. If a handler re-dispatches into `Toolbox::call` (`execute` included), break the mutual `async fn` `Send`-checking cycle (E0391) by returning an explicit concrete `Pin<Box<dyn Future<...> + Send + 'a>>` rather than bypassing `Toolbox::call` through `call_inner`. A re-dispatched tool reaches `Toolbox::call` directly, so its recursive-call guard must live in the handler (e.g. `execute::run` checks `IN_SCRIPT`), not only in the `execute` bridge that normally intercepts a recursive request.
4. Pinned lists: add the name to `OFFERED_TOOLS` in `crates/prompts/src/tests.rs` and to the expected MCP name list in `crates/tools/tests/tools.rs`. Extending `read`'s virtual targets (`el://docs`, `el://skills`) is the same kind of pinned change: dispatch before the jail in `read.rs`, then update the `read.path` description in `crates/tools/src/mcp.rs`, `crates/prompts/prompts/tool.read.md`, and the accepted-form list in `read_path_names_every_form_read_accepts` (`crates/tools/tests/contract.rs`).
5. Config the tool needs goes on `ToolConfig` (default `None`, an error message that names the missing config). Set it in all three daemon builders: `mcp_tool_config`, `toolbox_for` and `review.rs` `ReviewExecutor`.
6. The background review forks the Session request, so a tool declared to every Session is callable there only if `ALLOWED` in `crates/daemon/src/review.rs` lists it. The review's `read` is jailed to the Project and the global skills root, so give the tool a way to return any data the review must see.
7. API route: add the DTO to the `components` list and the handler to the `paths` list in `routes.rs`, then register the route. Regenerate `openapi.json` and `schema.d.ts` with `cargo run -p api --bin dump_openapi && (cd web && bun run generate:api)` (or rerun `scripts/check`) and stage both files.
8. Update the `AGENTS.md` of each crate touched.
9. Testing tools: `execute` captures Python `sys.exit` and tracebacks as `Ok(...)` text and returns `Err(ToolError)` only on harness or input-validation failures (such as blank `code`), so tests covering tool-error paths must trigger `Err` rather than a failing script body.
10. A wrapper that decorates failed calls (persisting them for retry, adding a hint) installs after the authorization early-return: wrapping before the gate records calls that must never run. It re-dispatches through `Toolbox::call`, not `call_inner`, which lacks the entry-layer arms (`execute`), and the retry handler must fail its own pre-dispatch errors without recording a new id while a retried allowlisted call that fails again records a fresh one. Persistence failures log and return the original error rather than hiding it.
11. Reference text the code serves to the model (`el://docs`, a generated config guide) names fields verified against the owning serde struct and the real file names; a settings key written from memory ships wrong and a reviewer or a following model acts on it. Delete each claim you cannot tie to a code symbol, and drive its topic names from one table so index, dispatch and unknown-topic error cannot drift.
