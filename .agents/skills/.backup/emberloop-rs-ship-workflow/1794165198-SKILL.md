# Ship an emberloop-rs change

Steps, in order:

1. Read the AGENTS.md chain for every crate you touch before editing. Write the failing test first, then fix.
2. Run focused tests while iterating (`cargo test -p <crate> --lib`). If you touched anything under `web/src`, run `npm --prefix web run build` first: the nextest test `the_embedded_web_bundle_is_newer_than_its_sources` fails on a `web/build` older than the sources. Then run `scripts/check` with `background: true` and wait once. It must pass unchanged; never weaken it. Its `openapi` stage rewrites `openapi.json` and `web/src/lib/api/schema.d.ts`; the `generated` stage then diffs both against git HEAD, so any API change fails until those files are staged (`git add openapi.json web/src/lib/api/schema.d.ts`). Staging is enough; ask before committing.
3. Build the release with `EMBERLOOP_HOME=<data root> HOME=<real home> scripts/release`. Set both variables explicitly: a Session HOME can be a harness-private directory, and the default home lookup then fails.
4. Install with `target/release/emberloop-daemon --data-root <data root> update --file "$PWD/target/release/emberloop-daemon" --session <current session id>`. The command only queues the update: it prints `Update X -> Y is queued`, and the daemon installs and restarts once the session is idle. Do step 5 after that restart, not right after the command.
5. Verify: `readlink <data root>/current` names the new release, `emberloop-daemon --version` matches, and `curl localhost:3000/api/version` agrees.
6. For a behavior change that reaches a live model, test it on a real Session. See `references/live-session-testing.md` for the endpoints, steer route check, and polling method.

Pitfalls:
- Do not kill the daemon by hand while any Session works; use the `update` command so the restart is orderly.
- Run `cargo fmt --all -- --check` first and list the `Diff in <file>` lines. Format only those files (`rustfmt <file>`), not the whole tree: `cargo fmt --all` reformats unrelated uncommitted files. Keep `pub mod` lines alphabetical; rustfmt reorders them and fails `scripts/check`'s fmt stage otherwise.
- A new required prop on a Svelte component breaks every existing test mount with a type error in `svelte-check`. Give new props a default (`onskills = () => {}`) unless every caller must pass one.
- Read the failing test's assertion before changing behavior: a test that pins the old behavior (e.g. a 409 for a feature being replaced) must be rewritten to the new contract, not left failing.
- A Session that started before the update has no frozen skill catalog (`<session>/skill-catalog.md` is written only when a Session starts). Say so; do not call it a bug.
- Clippy denies `tokio::time::sleep` in tests (`disallowed_methods`). Wait with a bounded `tokio::task::yield_now().await` loop; a live test that waits on a real model may `#![allow(clippy::disallowed_methods)]` for the file.
- To prove a proxy feature keeps the provider cache intact, run an `#[ignore]` live test (pattern: `crates/daemon/tests/review_live.rs`, `LIVE_CLAUDE_HOME`, `LIVE_CLAUDE_BIN`) and compare `(input, cached, created)` of the proxy `usage` events before and after the feature's side request. Do not set `Settings` through `PUT /api/settings` in a test daemon: the title-model check returns 400 without a model catalogue. Drive the default through the prompt instead.
- Never assume a fold or review feature works live from unit tests alone. State what was not checked in the final reply.
