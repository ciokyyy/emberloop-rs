# Change the emberloop-rs web UI

`web/` is one SvelteKit SPA with dark-only tokens, shadcn-svelte components over bits-ui, and Vitest/jsdom tests. Read `web/AGENTS.md` first; it owns the file map and the event-payload contract.

## Procedure

1. Locate the component by grepping the strings visible in the user's screenshot (a title, a button label), not by reasoning about pixel geometry. A phone screenshot shows the rendered result, never the class that caused it.
2. Read the component and `web/src/app.css` together: every colour utility must exist as a `--color-*` entry in the `@theme inline` block.
3. Change the smallest markup that carries the fix, then add or extend a Vitest case for the behaviour (a reducer case in `lib/*.test.ts`, a mount test beside the component).
4. `cd web && bun run check` (svelte-check covers tsc) and `bun run test`, then the repo `scripts/check`. This repo is bun-only.
5. Say plainly what was not verified. A class change is unverified until it is seen in a browser or on the phone; jsdom has no layout. `references/live-browser-checks.md` has the project-scoped URL, feed scroll and scratch-Session recipe for checking a rendered answer.

## Session sidebar bands

`Sidebar.svelte` lists each Session in exactly one band, first match wins: `Active` (status `working`, grouped by Project), `Recent` (touched in the last 10 minutes), then the current Project's remaining Sessions with the Project name as the only header. Claim ids into a `Set` while filtering, so a working Session never repeats in Recent or the current band.

- Build the parent/child nesting once over all Sessions, then filter that ordered list per band: nesting before filtering keeps reviewer children after their parent, and a child whose parent landed in another band still renders on its own.
- `Session.updatedAt` is Unix milliseconds, so a test fixture with `updatedAt: 0..2` is years old and silently drops out of Recent and out of a non-current Project. Use `Date.now() - n` in fixtures, and a timestamp older than `10 * 60 * 1000` when the case must sit outside the window.
- Band headers carry `data-testid="section-header"`, Project headers `data-testid="project-header"`; assert both when the banding is the point of the test.

## Porting a design mock into web/

1. Treat the mock as a spec, not a picture: read the frame's geometry (sizes, gaps, radii) and its colour tokens, then map every value to a token name. A raw hex in a component is a value nobody can retheme. A `.figcraft` file is a zip: read `document.json` and convert the named frame's `fills[0].color` floats to hex (0.945 × 255 = `#f1f1f1`); do not eyeball the downscaled thumbnail.
2. Land the tokens first, in one edit of `web/src/app.css`: the `:root` values plus a `--color-<name>` line in the `@theme inline` block for every token you add. A token without that alias emits no utility at all.
3. Rebuild the component's chrome to match the mock's own structure: pinned rows (header, toolbar, footer, an effort selector) are ordinary flex siblings, and the single scrolling region is `min-h-0 flex-1 overflow-y-auto`. Pinning is a layout decision, not a styling trick — content inside the scroll box scrolls away however it is painted.
4. Leave the dialog header row alone when the user says they will edit it by hand; restructure everything below it.
5. Grep the test files for every label, aria-label and role you renamed or removed, and update them in the same change.
6. `bun run check` and `bun run test` prove types and behaviour, not CSS: run `bun run build` too, because an unknown utility only fails there.

## Making the web UI installable (PWA)

`references/pwa-and-icons.md` holds the serving path and the icon geometry. Two decisions come first:

- The URL bar decides the display mode; the modes cannot be combined. `standalone` has no address bar on Chrome desktop, Android and the iOS home screen. Safari on iOS ignores `minimal-ui` and falls back to `browser`, so the bar comes back there only. `display: browser` is not installable in Chromium at all.
- Chromium installs on HTTPS plus a manifest (`name` or `short_name`, `start_url`, one icon, `display` in `standalone`/`fullscreen`/`minimal-ui`); a service worker is not required, so the smallest installable change is a manifest and icons. A daemon UI on loopback is a secure context, but `--allow-remote` on a LAN address over plain HTTP is not: no service worker, no install prompt.
- Icons are square and the platform rounds them. A `maskable` icon needs its mark inside the central 80% diameter, and iOS ignores `maskable` and squircle-crops its own `apple-touch-icon`, so bake the padding into the PNG artwork. A CSS `border-radius` on an `<img>` changes nothing the home screen shows.
- A notification carries no custom sound: the Notification API exposes only `silent` (the old `sound` member is gone). A chime is the page's own `<audio>` or Web Audio playback with `silent: true` set so the OS does not double it, and it only rings while a page is open. `references/pwa-and-icons.md` has the recipe.
- An alert that must ring with the app closed is not a page concern: the delivery channel sets the sound, and a self-hosted server on a remote host notifies that host, not the machine being looked at. Read the channel table in `references/pwa-and-icons.md` (page audio, Web Push, ntfy, Pushover, a native Rust shell) before proposing one.
- Web Push answers the closed-app case and brings its own limits: no custom sound anywhere, the push service sees endpoint and timing, iOS needs the app installed to the Home Screen first, and the daemon needs outbound internet to FCM or Apple. Dedupe it against the open page in the daemon, off a visibility heartbeat, so one event never rings twice. Mechanics in `references/pwa-and-icons.md`.

## Pitfalls

- An unknown utility class is silent: Tailwind v4 emits nothing for `bg-bg-1`, `bg-bg-2` or a bare `text-fg`, so the element renders transparent and the page shows through. The only tokens are `surface-0..3`, `fg-1..4`, `border`, `input`, `brand`, `brand-strong`, `on-accent`, `track`, `status-*` and `tool-*`, and a token added to `:root` needs its `--color-<name>` alias in the same `@theme inline` block or its utility stays silent too. When the user says a panel is transparent, grep `bg-bg-` and `text-fg"` before anything else; opaque overlays are `bg-surface-1`, page surfaces `bg-surface-0`.
- A view swapped into `<main>` below the 56px header must be `flex min-h-0 flex-1 flex-col`, never `h-full`. `h-full` is 100% of main, so the view starts at the header's 56px offset and still spans main's full height: its pinned footer (the Settings save bar) lands past the viewport, and `body` is `overflow: hidden`, so the user cannot scroll to Save. The inner scroll box stays `min-h-0 flex-1 overflow-y-auto`.
- A checked switch needs a track and thumb with different values. On the near-white `--brand` track a white thumb vanishes and the control reads as a dead pill. Use `--on-accent` (#111111) for the checked thumb and `--fg-3` for the unchecked one, matching the mock's Toggle (track `#f1f1f1` / knob `#111111` on, `#3e3e3e` / `#9e9e9e` off).
- Verify an ad-hoc browser check with `agent-browser` (`open`, `set viewport`, `eval`, `screenshot`, `close`). Do not write a Playwright script, even when another project already has playwright installed. Click by snapshot ref: `agent-browser snapshot` prints `button "Discard" [ref=e8]` and `agent-browser click @e8` works, while a `button:has-text("Discard")` selector fails with `Element not found`.
- Do not infer a defect from measured screenshot coordinates. If the wrong element is not legible in the picture, ask which one it is in one short question; a wrong guess costs more than the question.
- Mobile layout: the `sm` breakpoint is 640px. For a crowded horizontal bar, let it wrap below `sm` (`flex-wrap`, `basis-full` on the input row, `rounded-2xl`) and restore the single line above it (`sm:flex-nowrap`, `sm:rounded-full`), rather than shrinking children until they clip. Overlays in the FigCraft view sit on top of the upstream WASM editor's own floating toolbar, so keep them short.
- Links inside the FigCraft editor resolve in the same tab and no edit in `web/` retargets them: it is a prebuilt egui/WASM app (`scripts/install-figcraft` fetches it, the daemon serves `/usr/local/share/figcraft`, `FigcraftView.svelte` draws it into a canvas) whose hyperlinks default to `_self`. A new-tab requirement is an upstream change or a control we add beside the canvas.
- A link in this SPA is rarely an `<a href>`: navigation goes through `goto()` or `window.location.assign()` with the path helpers in `web/src/lib/route.ts` (`sessionPath`, `designPath`), or a handler prop (`onopendesign`). Grep those before telling the user a link does not exist, because an `href=`-only search misses the trigger and answers a different question than the one asked. Retarget one by replacing the call with `window.open(path, '_blank', 'noopener')` and keep the embedded route alive for deep links.
- bits-ui sets the same `data-highlighted` for pointer and keyboard. Any highlight-driven `scrollToIndex` on a virtualized list must ignore pointer-driven highlights (a flag set on `pointermove`/`pointerdown`, cleared by a capture-phase `keydown`), or a touch drag snaps back to the row under the finger.
- jsdom has no `MediaRecorder` or wake lock: stub them with `vi.stubGlobal('navigator', {...})` and `vi.stubGlobal('MediaRecorder', class {...})`. Unmount the component instead of stopping the recorder, because teardown nulls `onstop` and avoids the network call the stop would trigger.
- This suite is Svelte compile, so the Vitest pool dominates its runtime: forked workers re-pay the compile per worker file (138 s for 41 files) while `pool: "threads"` in `web/vite.config.ts` runs the same tests in 106 s and keeps the `scripts/check` web stage inside its budget. `--no-isolate` is faster still but breaks the tests that share module state (30 at last count), so never enable it to buy time.
- A voice note is a state machine, not a mic toggle: show the recording clock, a spinner on the button while transcribing, and on an upload failure keep the recorded Blob so the status row offers Retry (resend that same Blob) and Discard. A mic that silently returns to idle reads as broken and leaves no way back after a dropped network.
- Take glyph geometry from the packages instead of retyping paths: lucide data is `__iconData` inside `web/node_modules/@lucide/svelte/dist/icons/<name>.svelte`, and brand logos are raw svg files from `@lobehub/icons-static-svg` that `web/src/lib/brands.ts` imports with `?raw`. A hand-copied path drifts from the component that renders it.
- A long media capture needs a screen wake lock, or the phone sleeps and ends it: request it in an `$effect` keyed on the recording flag, re-request on `visibilitychange` when visible, and release it in the effect cleanup.
- Two side panels, one grammar: both rails take `--drawer-width`, `.drawer-scrim`, `.drawer-rail` and `--dur-standard`/`--ease-smooth` from `web/src/app.css`, and `design.md` at the repo root is the contract a later session reads. A vendored drawer (vaul behind `ui/drawer`) ships its own `transition: transform 0.5s cubic-bezier(0.32, 0.72, 0, 1)`, so the two rails open at different speeds however the classes are set; when the user asks for one speed, drop the library and use the shared classes. `references/drawer-grammar.md` holds the tokens and the dismiss rules.
- Flip a drawer at `max-width: 767.98px`, not `760px`: Tailwind's `md` is 768px, and a `760px` query leaves a band where the rail is fixed while the hamburger is hidden.
- One input format, one button size: a secondary surface that asks the agent something (the FigCraft HUD) reuses the composer's card — `rounded-2xl border border-input bg-surface-1 p-1`, a `rows="1"` textarea where Enter sends and Shift+Enter adds a line, a 32px `bg-brand` arrow send button — and every icon-only control stays `.icon-btn` (32px). A bespoke bar with a Select and a larger button reads as a different product and the user asks for it to be redone.
- A surface that drives a Session takes it from the URL, not from a switcher inside itself: `designPath(projectId, sessionId)` in `web/src/lib/route.ts` writes `?session=`, the route derives it (`page.url.searchParams.get('session')`), and the component resolves it against `sessions` by id. An in-surface session Select duplicates the sidebar. Degrade the URL-less case visibly: `No session` status, a placeholder that says to open the board from a session, a disabled prompt and no Open chat button; a mount test passes `currentSessionId` explicitly, because a removed fallback to `sessions[0]` otherwise leaves the box disabled in the test too.
- jsdom never sees `inert`: Svelte assigns it as a DOM property, so assert `aria-hidden` in the test and keep both attributes on the panel.
- Verify a transition in the browser with a delay. A click and `getComputedStyle` inside one `agent-browser eval` read the pre-click transform, so click in one eval, sleep ~0.6-1s, then read; report the transition (`0.18s`, `cubic-bezier(0.22, 1, 0.36, 1)`) together with the settled transform (`none` open, `matrix(1, 0, 0, 1, ±width, 0)` closed) and the scrim's `rgb(0 0 0 / 0.5)`.
- Wrap every `agent-browser eval` body in `(() => { ... })()`: consecutive evals share one global scope, so a reused `const a` fails with `SyntaxError: Identifier 'a' has already been declared` and the check is lost. Drive the page by `http://127.0.0.1:3000/...`, and set the viewport with `agent-browser set viewport 390 844` before `open` so the mobile branch is the one measured.
- Open a specific Session at `/p/<projectId>/s/<sessionId>`: `/sessions/<id>` redirects to the last Session of the project and renders a plausible feed for the wrong id. The feed is virtualized, so only in-view rows exist; scroll `.h-full.overflow-y-auto.px-4.py-4` to `scrollHeight` before counting elements. To check a rendered markdown feature, POST a scratch Session and a prompt that pins the exact markdown, then delete it. Recipe: `references/live-browser-checks.md`.
- A new event field reaches the UI in four places: the daemon payload (`serde_json::json!` in `crates/api/src/routes.rs`), the reducer in `web/src/lib/feed.ts`, the row markup (`Feed.svelte`), and the payload key list in `web/AGENTS.md`. A steer row carries its own fields; the delivered event only changes `route`, so a count must be set when the item is created.
- A flow that opens a device login (Claude, Codex) and then polls is a two-sided state machine: clear the local flow object in the poll's `catch` (`error`, `stopWatch()`, `flow = null`), else a page reloaded mid-flow keeps showing `running` forever and the daemon refuses the next attempt with `409 a <provider> login is already running`. Label a signed-in provider `Reconnect`, not only `Connect`: a credential file can exist and still be revoked.
- The Fallow health gate (`cd web && bunx fallow health --score --min-score 87.9`, also a `scripts/check` stage) is a scalar, `100 − penalties`, and the two dead-code penalties move whenever you generate a component or export a helper. Dropping a UI dependency orphans the vendored `ui/<name>/` folder that wrapped it (e.g. vaul behind `ui/drawer`): delete that folder and `bun remove` the package in the same change. A generated shadcn folder counts the same way until only the parts a caller imports survive. Clear your own dead code instead of refactoring the big pre-existing files — the floor sits 0.1 under a healthy tree, so the failing score is usually a delta. `references/fallow-gate.md` has the penalty reading, the baseline worktree check and the trim recipe.
- Flipping the accent to a light near-white turns every `bg-brand text-white` control white-on-white. Add an `--on-accent` token (#111111) with its `--color-on-accent` alias, set `color: var(--on-accent)` in the shared `.btn-pri` and `.seg[aria-pressed]` rules, and grep `bg-brand` and `text-brand` for the call sites that carry their own `text-white`.
- Tailwind v4's `aria-selected:` variant matches only `aria-selected="true"`, so underline tabs need no state class: put `-mb-px border-b-2 border-transparent` on each tab and `border-b` on the tab row, and the 2px active underline covers the 1px hairline instead of sitting a pixel below it. Keep `role="tab"`, the roving tabindex and `aria-controls` while replacing a segmented control with tabs.
- A tool result may tint a row as added or removed only when it really is a diff: `ToolBody`'s `rowClass` once tinted every line starting with `+`/`-`, so a markdown list or a source line in a read result read as a diff. Gate the whole `+`/`-`/`@@` decision on diff detection (an explicit `language="diff"`, a `diff --git`/`@@` header, or a `.diff`/`.patch` path), and pin it with a mount test that renders `- item` against a non-diff path and asserts no `.diff-del`/`.diff-add` row.
- Syntax colouring for a `file://` text preview reuses the regex tokenizers in `web/src/lib/highlight.ts`, chosen by extension in `fileEmbeds.ts` (`highlightJson`, `highlightDiff`, `highlightShell`, else `highlightCode`); the emitted spans carry the `tk-*` classes `app.css` already styles. Do not add shiki or highlight.js for this. Test the disclosure by stubbing `vi.stubGlobal('fetch', ...)`, setting `box.open = true`, dispatching `toggle`, then `vi.waitFor` on a `tk-*` span — jsdom never fires `toggle` on its own.
- A text disclosure and a page iframe belong on a `.md-files` shelf at the end of the answer, not inline: keep the original `a[data-file]` link in the sentence so the grammar survives, append the card to the shelf, and add the shelf only when it has children. Inline replacement leaves dangling punctuation such as `see [x](file:///…), for details.` written as `see , for details.` Images stay inline. CSS: `.md-files { display:grid; gap:6px; margin-top:0.6em }` and reset the child margin inside it.
- A list test that only asserts a title is present proves nothing about order or omission: compare `container.textContent.indexOf(...)` positions, as the Session sidebar band test does, or a regression that reorders a band still passes.
- Renaming a user-visible label (a breakdown category, a card title) breaks the jsdom test that asserts the old string, and a renamed prop or removed element breaks a role query elsewhere. Grep `web/src/**/*.test.ts` for the old wording in the same change rather than after the suite fails.
