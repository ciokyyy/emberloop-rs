# AGENTS.md — web

## Purpose

SvelteKit SPA for phase 1: Projects sidebar, Session feed, composer and Settings. Built with `adapter-static` (fallback `index.html`, SSR off), Tailwind CSS v4 and shadcn-svelte components over `bits-ui`. Every control is a shadcn-svelte component: add one with `bunx shadcn-svelte add <name>`; the generated files are only trimmed of what nothing imports. The daemon serves the static build at its own origin; `VITE_API_BASE` overrides the API origin in development.

## Layout

- `src/routes/+layout.svelte`: the app shell — Session selection, SSE stream, prompt/steer/cancel, Settings save. The URL owns what it shows, so a refresh, a pasted link and Back all land on the same screen: `/p/<project>/s/<session>`, `/p/<project>/new` (the draft), `/p/<project>/settings`, `/p/<project>/providers`, `/p/<project>/usage`, and `/<view>` when there is no Project to hang them on. Every other route file holds a comment only; `src/lib/route.ts` owns the URL grammar. SSE events are buffered and folded into one update per animation frame: a replay arrives as hundreds of frames in one task, and applying each one stalls the main thread on a long Session.
- `src/lib/api/index.ts`: typed `fetch` client for the routes in `crates/api`, prompts included. `types.ts` mirrors the DTOs; `schema.d.ts` is generated from `openapi.json` by `bun run generate:api`.
- `src/lib/components/Providers.svelte`: connected providers (Antigravity and ChatGPT sign-in flows, saved keys with Remove key) and a searchable Add provider list of the API-key providers (`ProviderView.auth === 'key'`), each with a password key input that saves through `PUT /api/providers/:id/key`. `Usage.svelte` lists connected providers; key providers show no usage numbers.
- `src/lib/feed.ts`: pure `SessionEvent` to `FeedState` reducer, plus `applySnapshot` for the server's open snapshot (status, usage and the todo list the tail window may not hold), covered by `feed.test.ts`. The `todos` event and the snapshot both carry `{items:[{id, content, status}]}` and touch no feed row. Paging older events never resets status, usage or todos. A `todo` tool row keeps only the first line of its result, so `set` and `read` never print the whole list in the feed.
- `src/lib/toolfeed.ts`, `compactFeed.ts`, `highlight.ts`: typed ports of the Go app's tool-row model (hues, exit codes, error tails, Explored grouping, diff stats, tokenizers). `toolRuns.ts` folds consecutive tool and thinking items into runs; `contextMeter.ts` computes the context ring percent and tone; the selected model’s window takes precedence over a previous model’s response window. Absent provider usage stays `null`: the ring shows `–` / usage unavailable and the dialog shows “Not reported yet”, never a fabricated 0%; reported nonzero input below 0.5% displays `<1%`. `contextBreakdown.ts` validates the proxy’s estimated category counts; usage events and reload snapshots carry them without adding feed rows.
- `src/lib/motion.ts`: Svelte transition helpers (`rise`, `slideUp`, `slideDown`, `fadeAt`, `collapse`, `flipAnimation`) ported from the Go app. They read the `--dur-*` and `--ease-smooth` tokens in `app.css` with their unit (the minifier ships `.18s`, not `180ms`) and go to zero duration under reduced motion. Transitions on an element inside an `{#if}` inside an `{#each}` need `|global`.
- `src/lib/components/PlanCard.svelte`: the plan card above the composer — collapsed to `done/total`, the active item and a progress bar; click or `p` toggles; the expanded list caps at 8 rows with `+N more` and repeats the active item when it falls outside them; `[ ]`, `[~]`, `[x]`, `[–]` with resolved rows struck through; opens for 2 s on a create or replace when `todo_auto_expand` is on and fades after the last item resolves when `todo_hide_when_done` is on (fake timers in `PlanCard.test.ts`). A todo reminder and the cap note render as dashed notice rows.
- `src/lib/components/`: Sidebar (a Project select whose first option adds a Project by path, then New session, then the URL Project's Sessions in a scrolling list, led by the draft row — titled New session, selected, its bar the picked model's harness colour — while the draft page is open: no brand heading, no Project header or count, and a folded title slides left and right while its row is hovered or selected, via `marqueeShift` in `lib/marquee.ts` and `app.css`; harness bars are Claude clay `#d6a87b`, pi-rs violet `#8b7cf6`, Antigravity blue `#5b9ac6`, height 5, and a Session's harness is its model's `source`, falling back to its name when the catalogue lost it), Feed (a queued steer stays pinned at the bottom, inside the log's column, until delivery puts it back in the log; a virtual row whose block is gone is skipped, because a shrinking feed reaches the virtualizer one flush before its count does), ToolFeed (compact tool rows, Explored groups, thinking blocks), ToolBody, ContextRing, WorkingIndicator (the Go app's activity line, in the composer's column directly above the card), Icon, Composer (context ring and model/effort triggers open one `SessionDialog`, attach, send/stop; remounted per Session so a draft never leaks across), Settings (Tool keys: Brave, Exa and Jina saved through `PUT /api/tool-keys/{name}`, which stores them for the tools themselves instead of a shell export, so the next tool call uses them; then Session titles, Proxy, Context: bands, floors, tiers, protected tools and the two inject switches, Todo), Prompts, ModelPicker and NewSessionDialog (the dialog only adds a Project by path: New session goes to the draft page instead, and the dialog keeps its model and level controls only for a direct create, so the draft page owns that pick); `ui/` holds the local shadcn-svelte Button, Switch and Select (the only Select parts in use). `SessionDialog.svelte` has Model and Context tabs: search by model/provider, keyboard-navigable tabs, model-specific catalogue efforts, idle-only model changes with surfaced errors, and `ContextDetails.svelte` for system prompts, tool definitions, tool calls/results, retained compression summaries and conversation estimates. The provider total is separate; image count is shown without claiming an image-token estimate. New Sessions also choose a model-specific effort.
- Image attachments support picker, paste and drop, five PNG/JPEG/WebP/GIF files up to 10 MiB each, previews and removal. Text-only models refuse attachments. A failed send keeps the draft and files; working Sessions refuse images rather than silently dropping them into a text-only steer. Composer teardown revokes preview URLs.
- `src/app.css`: dark-only tokens shared with the mock and the Go app.

## Event data convention

`feed.ts` reads these `SessionEvent.data` keys. Changing the API event payload requires this file and `feed.ts` together.

- `status`: `state`
- `prompt`: `text`, `imagesCount`
- `assistant_chunk`, `thinking_chunk`: `text`
- `tool_started`: `id`, `name`, `input`, `display`; `tool_finished`: `id`, `name`, `output`, `status`, `display`
- `steer_queued`: `id`, `text`; `steer_delivered`: `id`, `route`
- `notice`: `id`, `text`, `route` (`"cap"` marks the todo cap note)
- `todos`: `items` (the whole list, `{id, content, status}`)
- `compression`: `text`; `action` is `compress`, `decompress`, `nudge` or `preflight`, and a nudge also carries `kind`, `tokens` and `sinceLast`
- `usage`: `inputTokens`, `contextWindow`, optional `cachedTokens` and `cacheCreationTokens` (the provider's prompt-cache reads and writes; absent when unreported), optional `breakdown` (`system`, `toolDefinitions`, `toolCalls`, `toolResults`, `compression`, `conversation`, `images`, `imageCount`, `estimatedTokens`); categories are estimated text tokens, `images` is zero because image costs are unknown
- `error`: `message`

## Workflow

- `bun` only: `bun run check`, `bun run test`, `bun run build`. `bun.lock` is committed; `npm` and `package-lock.json` are gone. The root `scripts/check` runs the first two when `web/` exists.
- Tests are Vitest; jsdom is the environment. Reducer, image limits, tool hues, Markdown sanitising, composer routing and the model picker are covered.
- The static output is `web/build/`, embedded by the daemon through `rust-embed`.

## Model selection, drafts and usage

`ModelPicker.svelte` uses the shared Bits UI combobox, filters model IDs, labels and providers, and groups by harness/provider. Session dialog tabs are Context then Model, with native Svelte transitions and reduced-motion support from `motion.ts`. The header shows no model/status chips; sidebar markers identify harnesses.

New session opens the draft at `/p/<project>/new`: no Session exists yet, so the page holds the model and Ponytail level picks — defaults once per Project: first model, `ponytail_default_level` — and the first prompt creates the Session through `POST /api/sessions`, sends through `POST /api/sessions/:id/prompt` and lands on the real URL. The sidebar draft row wears the picked model's harness colour, so the colour reads before anything is stored. Without a Project the dialog asks for one by path, and its create also lands on the draft page.

The keyed Composer saves text under `emberloop-rs:draft:<sessionId>` in localStorage, restores on remount and clears only after successful submission; the draft page passes `draft:<project>`, so its text survives a navigation and is dropped once the Session starts. Attachments are not persisted. Layout handles `session_title` events by updating session names without adding feed rows. Settings exposes automatic titles and the SDK model picker. Usage renders backend quota windows and balances; refresh requests new read-only data without editing saved credentials.
