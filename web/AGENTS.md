# AGENTS.md — web

## Reviewer subagents

Session `parentId` and `reviewerRole` metadata keep openable subagent rows (`spec`, `standards`, `worker`, `scout`) after their parent in the sidebar, including visible orphans. The layout refreshes Sessions on `notice` / `action: subagent_created`. `feed.ts` retains optional `ReviewerReport` metadata from `steer_queued`; delivery only changes its route. `SubagentReport.svelte` renders incoming reports or errors with subagent role labels and links, optional ticket path, status, summary, Markdown disclosure and queued/delivered state, never a user bubble. Settings provide ordered fallback ladder editors (add, remove with minimum 1 rung, reorder `↑`/`↓`, per-rung `ModelPicker` and reasoning effort) for `spec_reviewer`, `standards_reviewer`, and `subagent_tiers` (`smol`, `mid`, `top`); changing a rung model resets that rung's `reasoning_effort` to `null`.


## Purpose

SvelteKit SPA for phase 1: Projects sidebar, Session feed, composer and Settings. Built with `adapter-static` (fallback `index.html`, SSR off), Tailwind CSS v4 and shadcn-svelte components over `bits-ui`. Every control is a shadcn-svelte component: add one with `bunx shadcn-svelte add <name>`; the generated files are only trimmed of what nothing imports. The daemon serves the static build at its own origin; `VITE_API_BASE` overrides the API origin in development. SvelteKit 3 keeps its config (`adapter`, preprocess, `$lib` alias) in `vite.config.ts`; `svelte.config.js` is gone and must not come back.

## Layout

- `src/routes/+layout.svelte`: the app shell — Session selection, SSE stream, prompt/steer/cancel, Settings save. The URL owns what it shows, so a refresh, a pasted link and Back all land on the same screen: `/p/<project>/s/<session>`, `/p/<project>/s/<session>/cache` (the prompt-cache page), `/p/<project>/new` (the draft), `/p/<project>/settings`, `/p/<project>/providers`, `/p/<project>/usage`, and `/<view>` when there is no Project to hang them on. Every other route file holds a comment only; `src/lib/route.ts` owns the URL grammar. SSE events are buffered and folded into one update per animation frame: a replay arrives as hundreds of frames in one task, and applying each one stalls the main thread on a long Session.
- `src/lib/api/index.ts`: typed `fetch` client for the routes in `crates/api`, prompts and `sessionUsage` (the `/usage` history) included. `types.ts` mirrors the DTOs; `schema.d.ts` is generated from `openapi.json` by `bun run generate:api`.
- `src/lib/components/Providers.svelte`: connected providers (Antigravity and ChatGPT sign-in flows, saved keys with Remove key) and a searchable Add provider list of the API-key providers (`ProviderView.auth === 'key'`), each with a password key input that saves through `PUT /api/providers/:id/key`. A signed-in Claude subscription shows `Reconnect`, because the daemon cannot tell a revoked token from a live one and the login is how it is replaced; a login already running is adopted by the next click, and its new credential is written into every Session home so a broken agent heals on its next turn. A flow the panel can no longer poll is cleared, which brings the button back. `Usage.svelte` lists connected providers; key providers show no usage numbers.
- `src/lib/feed.ts`: pure `SessionEvent` to `FeedState` reducer, plus `applySnapshot` for the server's open snapshot (status, usage and the todo list the tail window may not hold), covered by `feed.test.ts`. The `todos` event and the snapshot both carry `{items:[{id, content, status}]}` and touch no feed row. Paging older events never resets status, usage or todos. A `todo` tool row keeps only the first line of its result, so `set` and `read` never print the whole list in the feed.
- `src/lib/toolfeed.ts`, `compactFeed.ts`, `highlight.ts`: typed ports of the Go app's tool-row model (hues, exit codes, error tails, Explored grouping, diff stats, tokenizers). `toolRuns.ts` folds consecutive tool and thinking items into runs; `contextMeter.ts` computes the context ring percent and tone; the selected model’s window takes precedence over a previous model’s response window. Absent provider usage stays `null`: the ring shows `–` / usage unavailable and the dialog shows “Not reported yet”, never a fabricated 0%; reported nonzero input below 0.5% displays `<1%`. `contextBreakdown.ts` validates the proxy’s estimated category counts; usage events and reload snapshots carry them without adding feed rows.
- `src/lib/cache.ts`: pure prompt-cache model over the `/usage` rows: latest hit percent, token-weighted Session hit percent (`sum(cached) / sum(prompt)`, never a mean of percents), the trend points, the cold-start flag and `percentLabel` (a dash for null, `<1%` for a trace). `CacheView.svelte` is the page (`Prompt cache`): it reloads the history (200 requests, the server's default window) when the Session's status changes, shows `Loading…`, an error alert, an empty state, and a notice when the provider reports no cache fields (null percents are never shown as 0%). A full window is labelled `Across the last 200 requests`, so the Session figure never claims more than it counted. `CacheTrend.svelte` is the inline SVG trend (0-100 axis, labelled, `role=img` with title and desc). The page is reached from the Context tab's `Prompt cache` button (`ContextDetails`, through `SessionDialog`'s `oncache`).
- `src/lib/motion.ts`: Svelte transition helpers (`rise`, `slideUp`, `slideDown`, `fadeAt`, `collapse`, `flipAnimation`) ported from the Go app. They read the `--dur-*` and `--ease-smooth` tokens in `app.css` with their unit (the minifier ships `.18s`, not `180ms`) and go to zero duration under reduced motion. Transitions on an element inside an `{#if}` inside an `{#each}` need `|global`.
- `src/lib/components/PlanCard.svelte`: the plan card above the composer — collapsed to `done/total`, the active item and a progress bar; click or `p` toggles; the expanded list caps at 8 rows with `+N more` and repeats the active item when it falls outside them; `[ ]`, `[~]`, `[x]`, `[–]` with resolved rows struck through; opens for 2 s on a create or replace when `todo_auto_expand` is on and fades after the last item resolves when `todo_hide_when_done` is on (fake timers in `PlanCard.test.ts`). A todo reminder and the cap note render as dashed notice rows.
- `src/lib/components/`: Sidebar (a Project select whose first option adds a Project by path, then New session, then the URL Project's Sessions in a scrolling list, led by the draft row — titled New session, selected, its bar the picked model's harness colour — while the draft page is open: no brand heading, no Project header or count, and a folded title slides left and right while its row is hovered or selected, via `marqueeShift` in `lib/marquee.ts` and `app.css`; harness bars are Claude clay `#d6a87b`, pi-rs violet `#8b7cf6`, Antigravity blue `#5b9ac6`, height 5, and a Session's harness is its model's `source`, falling back to its name when the catalogue lost it), Feed (a queued steer stays pinned at the bottom, inside the log's column, until delivery puts it back in the log; a virtual row whose block is gone is skipped, because a shrinking feed reaches the virtualizer one flush before its count does), ToolFeed (compact tool rows, Explored groups, thinking blocks), ToolBody, ContextRing, WorkingIndicator (the Go app's activity line, in the composer's column directly above the card), Icon, Composer (context ring and model/effort triggers open one `SessionDialog`, attach, send/stop; a voice recording holds a screen wake lock so the screen does not sleep under it; remounted per Session so a draft never leaks across), Settings (Tool keys: Brave, Exa and Jina saved through `PUT /api/tool-keys/{name}`, which stores them for the tools themselves instead of a shell export, so the next tool call uses them; then Session titles, Proxy, Context: bands, floors, tiers, protected tools and the two inject switches, Todo), Prompts, ModelPicker (the open list scrolls to the highlighted row only when a key moved it: a pointer highlight would otherwise drag a touch scroll back under the finger) and NewSessionDialog (the dialog only adds a Project by path: New session goes to the draft page instead, and the dialog keeps its model and level controls only for a direct create, so the draft page owns that pick); `ui/` holds the local shadcn-svelte Button, Switch, Slider, AlertDialog and Table (Body, Cell, Head, Header, Row, Root; the generated caption and footer are trimmed). `SessionDialog.svelte` has Model and Context tabs: search by model/provider, keyboard-navigable tabs, model-specific catalogue efforts, idle-only model changes with surfaced errors, and `ContextDetails.svelte` for system prompts, tool definitions, tool calls/results, retained compression summaries and conversation estimates. The provider total is separate; image count is shown without claiming an image-token estimate. New Sessions also choose a model-specific effort.
- Image attachments support picker, paste and drop, five PNG/JPEG/WebP/GIF files up to 10 MiB each, previews and removal. Text-only models refuse attachments. A failed send keeps the draft and files; working Sessions refuse images rather than silently dropping them into a text-only steer. Composer teardown revokes preview URLs. A voice note shows its recording time, a transcribing spinner and, when the upload fails, the error with Retry (the audio is kept) and Discard.
- `src/app.css`: dark-only tokens shared with the mock and the Go app. The `.md` rules style answer Markdown (preflight strips list markers, so lists, headings, quotes and images are restored there); a long key or URL wraps (`overflow-wrap: anywhere`) except in code and tables, which scroll.
- `src/lib/fileEmbeds.ts`: a `file://` link or image in an assistant answer. `renderMarkdown(text, sessionFileBase(id))` rewrites it to `GET /api/sessions/:id/file?path=` and keeps the path in `data-file`; the `fileEmbeds` action on the assistant row then shows an image inline, an HTML file in a `sandbox=""` iframe, and a text-like file (JSON, logs, source) in a disclosure fetched on first open. Anything else stays a link opened in a new tab. `Feed` takes `sessionId` for this; without it `file:` links are dropped by the sanitiser.
- Installable app: `web/static/` holds the files `adapter-static` copies into `web/build/` — `manifest.webmanifest` (`display: standalone`, so the installed window has no URL bar), `sw.js`, the five icons and the links `app.html` adds (`manifest`, `theme-color`, `apple-touch-icon`, favicon). The icons and the favicon are generated, never exported by hand: `scripts/gen-icons` decodes `docs/logo.png` in bun, fills the mark's own `#0f1117` background full-bleed and fits the mark inside the maskable 80% safe circle, then writes `icon-192`, `icon-512`, `icon-maskable-512`, `apple-touch-icon` (180) and a 32 px `favicon.ico`; `scripts/gen-icons --check` fails when a committed icon is stale. `sw.js` has a `push` listener and a `notificationclick` listener and no `fetch` handler, so nothing is cached and a new shell is never hidden behind an old worker.
- `src/lib/notify.ts`: the alert path. `playAlert` plays a `uisfx` cue (`success` for a finished turn, `error` for a failed one), unlocked by the first pointer or key press because an AudioContext may not start on its own. `registerWorker` registers `/sw.js`; `enablePush` asks permission and stores the browser's subscription with `POST /api/push/subscribe`; `reportVisible` heartbeats `/api/push/visible` every 20 s while the page shows a Session, which is what makes the daemon skip its push. The layout hears the `idle` status or `error` event on its own SSE stream, alerts only for an event that landed after the page opened (a replayed tail is history, not news) and only while the tab is visible, and shows the dismissible notice bar with `Dismiss` and, for another Session, `Open`. Settings' Notifications row is the user gesture that asks for permission and sends one test push.
- `ProjectDrawer.svelte` is the right rail behind the project-header tools icon, with one FigCraft action, which opens `designPath` in a new window with `window.open(..., '_blank', 'noopener')`: an installed app has no URL bar to come back with, so the canvas owns its own window and the embedded `/design` route stays for deep links and the back gesture. Both rails follow the drawer grammar in `design.md` and `src/app.css` (`--drawer-width` 280 px, `.drawer-scrim`, `.drawer-rail`, `--dur-standard`/`--ease-smooth`, dismissed by scrim, Close or Escape): a 13 px title row with a 32 px icon button, an 11 px uppercase `Tools` group label and a 10 px-radius row (`sel` when it is the only one). The design view renders no static sessions rail, so the canvas owns the width; its `☰` stays visible at every width and opens the same rail as an overlay (`.drawer-floating` above 768 px). `FigcraftView.svelte` hosts the unmodified upstream WASM editor on its own `figcraft_canvas` (no iframe or custom renderer); `figcraft-web.ts` loads the pinned 0.16.0 assets from the daemon and joins the project through the same-origin WebSocket proxy. Design navigation reloads the document to release upstream GPU/input handlers. `FigcraftAgentHud.svelte` is a collapsed agent pill parked bottom-right so it never covers the editor's bottom toolbar: its Bot button toggles the open bar and dragging the button moves the pill, clamped to the window; a drag does not toggle. Reopening or a window resize re-clamps the offset, so a dragged pill never comes back off screen, and below 640 px the offset resets because the sheet is full width. The open bar keeps the composer's input format — a rounded card, a one-row textarea where Enter sends and Shift+Enter adds a line, a brand arrow send button — then a 32 px `Open chat` icon button, with send errors surfaced and the SSE status line above. The board's Session is the agent: it comes from `?session=` in the design link (`designPath(projectId, sessionId)` in `route.ts`), so there is no session switcher inside the HUD, and Open chat returns to that Session's feed. Below 640 px the opened pill turns into a full-width bottom sheet (status, then the prompt card, then open chat) instead of a bar that cannot fit. The vendored `ui/drawer`, `ui/select` and `ui/input` components were deleted once the rails and the HUD stopped using them; every remaining `ui/*` component still has a caller.
- `SessionMenu.svelte` wraps the header title and opens on a 450 ms hold (`holdToLift` in `lib/hold.ts`, cancelled by a drag or a scroll) or a right click, with `Copy link` and `Copy session reference` — the three-line block (`Session:`, `Project: name (root)`, `URL:`) the installed app has no URL bar to supply. Settings and Deep links still own the URL; the menu never navigates. It is built from the house `ui/popover` and `ui/button`, so add those components the way the catalog above does: only what a caller imports survives, and the generated parts nothing imports are deleted.
- `Skills.svelte` shows every skill the daemon sees for the URL Project plus the global root, whatever the origin: one `GET /api/skills?project=<id>` call feeds two sections (`This project`, `Global`) each with a count, and each row carries its origin chip (`agent`, `downloaded`, `human`). A project skill shadows a global one of the same name. The detail pane keeps the SKILL.md text, its support files and the backup history with the usage log.
- Page-host startup waits for `figcraft:ready`, then executes `collab.join` through `window.figcraft`; URL invites open a confirmation dialog instead. The host downloads `figcraft:save` payloads as `ArrayBuffer` bytes so native exports still work. Use the `agent-browser` CLI for browser verification, including real browser/MCP edits, reload persistence, the drawer and pill input; stub prompt HTTP when a real model call is not intended.
- For FigCraft development, set `EMBERLOOP_DEV_API` so Vite proxies API requests, live WebSockets and upstream editor assets through the same origin.

## Event data convention

`feed.ts` reads these `SessionEvent.data` keys. Changing the API event payload requires this file and `feed.ts` together.

- `status`: `state`
- `prompt`: `text`, `imagesCount`
- `assistant_chunk`, `thinking_chunk`: `text`
- `tool_started`: `id`, `name`, `input`, `display`; `tool_finished`: `id`, `name`, `output`, `status`, `display`
- `steer_queued`: `id`, `text`, `imagesCount`; `steer_delivered`: `id`, `route`. The steer bubble keeps the count the composer sent with it.
- `notice`: `id`, `text`, `route` (`"cap"` marks the todo cap note)
- `todos`: `items` (the whole list, `{id, content, status}`)
- `compression`: `text`; `action` is `compress`, `decompress`, `nudge` or `preflight`, and a nudge also carries `kind`, `tokens` and `sinceLast`
- `usage`: `inputTokens`, `contextWindow`, optional `cachedTokens` and `cacheCreationTokens` (the provider's prompt-cache reads and writes; absent when unreported), optional `breakdown` (`system`, `toolDefinitions`, `toolCalls`, `toolResults`, `compression`, `conversation`, `images`, `imageCount`, `estimatedTokens`); categories are estimated text tokens, `images` is zero because image costs are unknown
- `error`: `message`

## Workflow

- `bun` only: `bun run check`, `bun run test`, `bun run build`. `bun.lock` is committed; `npm` and `package-lock.json` are gone. The root `scripts/check` runs the first two when `web/` exists.
- Tests are Vitest; jsdom is the environment, and `vite.config.ts` runs them in the `threads` pool because the suite is Svelte compile and a fork per worker file re-pays it (138 s forked, 106 s threaded on the development host, which is what keeps the web stage inside its budget). `--no-isolate` is faster still but breaks 30 tests, so it is not used. Reducer, image limits, tool hues, Markdown sanitising, composer routing and the model picker are covered.
- The static output is `web/build/`, embedded by the daemon through `rust-embed`.

## Model selection, drafts and usage

`ModelPicker.svelte` uses the shared Bits UI combobox, filters model IDs, labels and providers, and groups by harness/provider. Session dialog tabs are Context then Model, with native Svelte transitions and reduced-motion support from `motion.ts`. The header shows no model/status chips; sidebar markers identify harnesses.

New session opens the draft at `/p/<project>/new`: no Session exists yet, so the page holds the model and Ponytail level picks — defaults once per Project: first model, `ponytail_default_level` — and the first prompt creates the Session through `POST /api/sessions`, sends through `POST /api/sessions/:id/prompt` and lands on the real URL. The sidebar draft row wears the picked model's harness colour, so the colour reads before anything is stored. Without a Project the dialog asks for one by path, and its create also lands on the draft page.

The keyed Composer saves text under `emberloop-rs:draft:<sessionId>` in localStorage, restores on remount and clears only after successful submission; the draft page passes `draft:<project>`, so its text survives a navigation and is dropped once the Session starts. Attachments are not persisted. Layout handles `session_title` events by updating session names without adding feed rows. Settings exposes automatic titles and the SDK model picker. Usage renders backend quota windows and balances; refresh requests new read-only data without editing saved credentials.
