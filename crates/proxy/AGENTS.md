# AGENTS.md — crates/proxy

## Purpose

Model-wire proxy for every harness.
- `router` serves `/health` and `/p/:token/*rest`; `TokenSigner` verifies `hex(session_id).hex(HMAC-SHA256(secret, session_id))`, so a path only reaches the Session it was signed for.
- `handle_generation` and `wire.rs` support Cloud Code (`Google`), OpenAI Chat (`/chat/completions`), Anthropic (`/messages`), and OpenAI Responses (`/responses`) wires: injects pinned policy, Ponytail, caveman and (when `ProxyConfig::codebase_memory` is set, i.e. the daemon found a usable code graph) the `skill.codebase-memory` text into the wire's system field (`systemInstruction`, `messages[0]`, `system`, or `instructions`), appends missing `compress`/`decompress`/`search_context`/`acp_status` declarations to `tools` when `inject_tool` is on, and maps conversation turns through core format so `NativeCompressor`, `SpliceStore`, and Route 1 mid-turn steering work across all wires.
- `x/<provider>/<path>` routes a fixed key or OAuth provider (`emberloop_core::providers::proxy_provider`) to its origin plus `<path>`; the wire comes from the path suffix, the client’s authentication/account headers pass through, an unknown id is 404. `ProxyConfig::with_provider_origin` replaces every origin for tests.
- Codex OAuth uses `/x/openai-codex/backend-api/codex/responses`, routed to `https://chatgpt.com/backend-api/codex/responses` as the Responses wire, never to OpenCode Go. The proxy only forwards the current request’s OAuth/account headers; it does not resolve, persist or refresh subscription credentials. `encoding.rs` bounds zstd decoding by the same 128 MiB generation cap, then `send_stream` re-encodes mutated JSON when the caller sent zstd, preserving correct content encoding and recalculating length. Invalid encoding is 400 and oversized decoded bodies are 413. Plain non-generation forwards retain their original bytes.
- SSE and JSON responses run proxy tool calls (`compress`, `decompress`, `search_context`, `acp_status`) locally and publish `EventKind::Compression` on the `EventBus` when a fold, restore or nudge runs; a pure proxy turn issues a follow-up request into the same client response, a mixed turn keeps only the harness calls and stores the proxy pair as a splice. `MAX_TOOL_ROUNDS` is 8, each round has `ROUND_TIMEOUT`, and a dropped client body drops the upstream stream.
- `execute_tool` runs `compress`, `decompress`, `search_context` and `acp_status` on the conversation; the harness never sees a proxy call. Every result carries a `📦 [acp] <tool>` marker or a `❌ [acp] <tool>` marker; model-forged marker lines are stripped from outgoing model text and from the `_raw` copy.
- `compress` takes `ranges: [{start, end, summary, topic?}, ...]` (the single `start`/`end`/`summary` form is still parsed). `Compressor::compress_batch(contents, calls, &CompressPolicy)` takes the policy per call and numbers every range against the history as it is now. It validates all of them first (bounds, non-empty summary, preserved recent tail, the latest user message, protected tools; an error names the range), so a bad batch changes nothing. Then, in history order, a range that overlaps an earlier one is skipped: the earlier range folds, and the report carries a `Warning:` line saying the later turns were not folded. Block ids follow history order and folds run from the highest range down. The batch is all-or-none: it stages on a copy, and a spill failure removes the files already written and leaves the history, blocks and next id as they were.
- `SpliceStore` persists to `<data root>/sessions/<id>/splices.jsonl`, append-only, keyed only by the tool-result turn id. `Splice::marker` is the exact string that proves a splice is already applied, so double-apply is impossible; a missing harness anchor drops the splice, a self-anchored proxy pair attaches before the newest turn. Opaque fields and thought signatures stay byte-exact.
- `meter::extract_usage` reads `usageMetadata`/OpenAI `usage` from JSON or the last SSE payload, including the cached prefix each wire reports (`cachedContentTokenCount`, `prompt_tokens_details.cached_tokens`, `cache_read_input_tokens`); usage is published as soon as its bytes are read from the upstream stream (`SseState::capture_usage`), never deferred to the stream end, because a harness may stop reading right after the answer and a cancelled body future would lose the meter. Each payload carries `contextWindow` resolved from the live model catalogue (`api::models::ModelCatalogue`) for the Session's model, so the UI meter follows a refreshed window instead of its own boot snapshot, and `cachedTokens`, the number that says whether compression kept the prefix cached. On non-Google wires `meter::thinking_delta` reads streamed reasoning text, published as `thinking_chunk`; the pi harness therefore drops its own ACP thought chunks (`AcpLaunch::forward_thoughts`) to avoid duplicates.
- `Compressor` trait: `compress_batch`, `decompress`, `search_context`, `status`, `fold_report`, plus `apply_skipping` to refold a harness-rebuilt history. A fold is found by its stored turns in order (at most 4 unrelated turns between neighbours), ignoring `thoughtSignature` and `_raw` (the chat wires wrap every turn in a `_raw` copy the proxy's own turns lack). Only the matched turns are replaced, by the summary turn where the first one stood; unrelated turns between them stay in the request, except turns marked `_nudge` (the transient nudge only the request carrying it holds) and turns the `SpliceStore` would put back (`SpliceStore::turns`, passed as `skip` to `apply_skipping`), which are dropped with the fold. A spliced turn is recognised by its function-call id as well as by equality: a pair changes shape on the wire round trip (name, marker field). Blocks are tried widest first and then repeatedly until nothing moves (a chain of folds over markers takes one round each), so a fold over an earlier fold's raw turns wins and a fold that stored an earlier marker still cascades. `NativeCompressor` swaps a turn range for a summary marker and spills originals to `<session spill>/blocks/<id>.json`; `wire::write_core_contents` strips `_nudge` so no upstream sees it.
- `NativeCompressor::new` reloads `blocks/*.json`, including exact summary turns and restored flags, and advances block ids beyond the largest stored id. Malformed or unreadable block files fail runtime creation rather than being overwritten. A block file without its `summaryTurn` fails runtime creation the same way; no older format is read. Writes use a temporary file and rename; they do not guarantee power-loss durability.
- `reset_history` archives the block directory as `blocks-reset-N` before starting an empty compressor for a new harness conversation. Archived originals remain on disk. Compressor originals and touched Session runtimes still remain in RAM; spilling is not a memory eviction policy.

## Context breakdown

`context.rs` classifies the final outgoing request on all four wires (including Google's `request` wrapper). Each response usage event carries `breakdown`: `system`, `toolDefinitions`, `toolCalls`, `toolResults`, `compression`, `conversation`, `images`, `imageCount`, `estimatedTokens`. Text estimates use UTF-8 bytes / 4 rounded up; structured tools include their serialized fields. Image payloads are excluded, counted as images only (`images` stays zero), and no category is claimed to be exact or forced to equal provider input usage. Compression is retained native summary text, not folded originals. Buffered continuations use their final request; streaming continuations clear per-request usage deduplication even when provider counts happen to match. Only aggregate counts, not prompt or image contents, reach the UI. Generation bodies are capped at 128 MiB so five maximum-size base64 image attachments plus conversation overhead fit. `tests/context.rs` covers classification and media exclusion; fake-upstream tests cover injection, compression, large image bodies and Codex’s zstd request / nested `response.completed` usage / mid-turn steer path, plus a streamed proxy-only compression call whose recompressed follow-up carries folded context and a lower provider-reported input count.

## Oversized tool results

`ctx.rs` is the reference's CCR (`kernel/src/ccr.ts`) on our own store. In `prepare_request` every tool result of 4000 estimated tokens or more (the reference's `minToolTokens`; the tools' own 10 KiB spill with a head/tail preview comes first) becomes a deterministic placeholder naming a `ctx:` handle, and the original is written once under `<session spill>/`, where `read ctx:<handle>:<start>-<end>` and `ctx_search` already page it back. The records live in `<session>/ctx.jsonl`. Replace-once: the placeholder is recomputed from the recorded entry, never from fresh bytes, so a harness that resends the raw result gets identical text and the upstream prefix cache stays intact. Both the core part and the `_raw` chat message are rewritten, because `core_to_chat` prefers `_raw`. A `read ctx:` page is never replaced again. Call/result pairing is never touched: only the result's text changes. It runs before the splices and the compressor, because a fold stores the handle and the handle must be back before a later request's fold is matched.

## Prefix stability

The provider's prompt cache hits only when a request starts with the bytes of the previous one. The harness resends its whole history, so the proxy rebuilds the same bytes for every turn it already sent.
- Fixed per process: the system prompt and the tool declarations (`PinnedPrompts`).
- Changes an earlier turn once, then keeps it: a `ctx` handle replacing an oversized result on arrival, the first emergency truncation, a `compress` or preflight fold from its start turn on, and `reset_history`. No other path may change an earlier turn.
- Transient, never in the prefix: the nudge sits after the newest tool result and `write_core_contents` strips its marker.
- Emergency truncation is sticky. An emergency nudge sets `SessionRuntime::emergency_truncated`; every later request then truncates its older results on the outgoing copy with the same rule, until a `compress`, a preflight fold or `reset_history` clears it. The band is judged on the usage of the truncated body, so without the flag the emergency flips on and off. The flag is in memory only: a restarted proxy starts clear and may flip once.
- Known gap: a proxy-only `compress` pair is re-attached before the newest model turn (`splice.rs` `replay_index`), so it moves on every request. The mid-run compress scenario is `#[ignore]`d until that is fixed. The regression tests are listed under Tests.

## Nudge gate

`nudge.rs` is the pure ticket-20 gate: `NudgeState::observe_with(tokens, window, compressible, active_blocks, config)` fires the first nudge at `min(75000, window / 2)` once per gate. Pressure over `maxContextLimit` and emergency over `emergencyThresholdPercent` fire on every turn while over, ahead of the first nudge, with compressible mass at least `minPressureBenefitTokens` (default `max(5000, window / 100)`). After a nudge, another repeats whenever the context has grown by `NUDGE_GROWTH_TOKENS` (50000) since the last one; the reference falls to the current count when the context shrinks. Tier 2/3 fire once when the active block count reaches their trigger and usage is under the pressure band. `reset_after_compress` closes the gate and clears the tier flags. `load` and `save` keep the state in `<session>/nudge.json` (temp file, then rename).

Wiring: `prepare_request` reads a Settings snapshot, passes the compressor policy (`preserveRecentMessages`, `protectedTools`) to each fold, strips forged markers, runs the preflight backstop (folds `1..` up to the preserved tail and never reaches the latest user message) when the input alone is over the window, then calls `inject_nudge` on the final contents. Tokens are the last published input usage, or chars / 4 of the turns when none exists; a successful `compress` clears that usage so the next request judges the folded history. The window is the catalogue window; no window means no nudge. The compressible range is turns `1..len-preserveRecentMessages` (start inclusive, end exclusive, as `compress` numbers them), counted at chars / 4. A fired nudge renders `nudge.first`, `nudge.pressure`, `nudge.emergency`, `nudge.tier2` or `nudge.tier3` and is put into the outgoing contents right after the newest tool result. It is transient: no splice stores it, so a later request carries it only when the gate fires again. A turn without a tool result gets no nudge. The gate is observed on a copy and committed (`SessionRuntime::commit_nudge`, saved to `nudge.json`) only when upstream answers with a success status; a failed, cancelled or refused request leaves it open, so the model still gets the nudge on the retry. Injection runs last, on the final contents after the splices, so its turn numbers match what `compress` sees. An emergency nudge also sets the sticky truncation of large visible tool results (see Prefix stability); summaries and the stored history are untouched. `injectTool` and `injectNudge` switch the declarations and nudges off independently; `proxy_compression` is the master switch. The event is `compression` with `action: "nudge"`, `kind`, `tokens`, `sinceLast` and `text`; preflight folds publish `action: "preflight"`, and a request where no stored fold matched publishes `action: "fold-miss"` with `Compressor::fold_report`'s line (the block, where its stored turns started matching, and the first turn that differed). `EMBERLOOP_PROXY_DUMP` writes the stable `<session>.in/.out.json` plus a rotating `<session>.<stage>.<NNN>.json` per request, keeping the newest 60, so two consecutive bodies can be diffed.

`acp_rule` stays out by the ticket decision.

## Tests

`tests/nudge.rs` covers the gate per window size, the band rules, configurable bands, tier triggers, the compress reset, the serde round trip, and replays `parity/golden/` decisions (inject, over-limit, emergency; never reason strings). The silent-frame test allows exactly the first-threshold frames in `KNOWN_EARLY` and pins each golden's first-fire counts in `FIRST_FIRES`; any other drift fails. Golden tests read the files at test time and need no Node.

`tests/compressor_characterization.rs` pins the `Compressor` through its public API (turn matching, refold and skip, `fold_report`, summary marker, token estimate, policy, batch validation) against `tests/fixtures/compressor/`.

`src/tests.rs` prefix-stability tests drive a growing Session through the fake upstream; each request must open with the previous one, except its nudge turn, its newest turn and the breaks in the table in that file's doc comment. They cover steady growth, the first nudge, a reset and the emergency flip-back, and the flag clearing on a compress and on a preflight fold. `src/tests.rs` nudge tests: the first nudge rides the tool-result turn once and replays byte-exact, nothing fires below the threshold, and the gate survives a runtime rebuild through `nudge.json`. A failed (500) or cancelled upstream request leaves the first nudge for the retry. It also covers protected tools and the preserved tail, `acp_status` numbers against a golden frame, marker stripping, emergency truncation, preflight folding, and the `injectTool`/`injectNudge` switches. The compress-reset path is covered only by unit tests.
`src/tests.rs` runs a fake upstream and a fake model catalogue. Covers token tamper, prompt/tool injection, usage with its window, byte-exact splice replay after reload, dropped-anchor and double-apply rules, SSE proxy-only continuation, mixed-turn rewriting, the 8-round cap, client disconnect, and round timeout.
