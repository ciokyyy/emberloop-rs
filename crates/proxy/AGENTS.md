# AGENTS.md — crates/proxy

## Purpose

Model-wire proxy for every harness.
- `router` serves `/health` and `/p/:token/*rest`; `TokenSigner` verifies `hex(session_id).hex(HMAC-SHA256(secret, session_id))`, so a path only reaches the Session it was signed for.
- `handle_generation` and `wire.rs` support Cloud Code (`Google`), OpenAI Chat (`/chat/completions`), Anthropic (`/messages`), and OpenAI Responses (`/responses`) wires: injects pinned policy, Ponytail and caveman text into the wire's system field (`systemInstruction`, `messages[0]`, `system`, or `instructions`), appends missing `compress`/`decompress`/`search_context`/`acp_status` declarations to `tools` when `inject_tool` is on, and maps conversation turns through core format so `NativeCompressor`, `SpliceStore`, and Route 1 mid-turn steering work across all wires.
- SSE and JSON responses run proxy tool calls (`compress`, `decompress`, `search_context`, `acp_status`) locally and publish `EventKind::Compression` on the `EventBus` when a fold, restore or nudge runs; a pure proxy turn issues a follow-up request into the same client response, a mixed turn keeps only the harness calls and stores the proxy pair as a splice. `MAX_TOOL_ROUNDS` is 8, each round has `ROUND_TIMEOUT`, and a dropped client body drops the upstream stream.
- `execute_tool` runs `compress`, `decompress`, `search_context` and `acp_status` on the conversation; the harness never sees a proxy call. Every result carries a `📦 [acp] <tool>` marker or a `❌ [acp] <tool>` marker; model-forged marker lines are stripped from outgoing model text and from the `_raw` copy.
- `compress` takes `ranges: [{start, end, summary, topic?}, ...]` (the single `start`/`end`/`summary` form is still parsed). `Compressor::compress_batch` numbers every range against the history as it is now, validates all of them first (bounds, non-empty summary, no overlap, preserved recent tail, protected tools; an error names the range) so a bad batch changes nothing, gives block ids in history order and folds from the highest range down.
- `SpliceStore` persists to `<data root>/sessions/<id>/splices.jsonl`, append-only, keyed only by the tool-result turn id. `Splice::marker` is the exact string that proves a splice is already applied, so double-apply is impossible; a missing harness anchor drops the splice, a self-anchored proxy pair attaches before the newest turn. Opaque fields and thought signatures stay byte-exact.
- `meter::extract_usage` reads `usageMetadata`/OpenAI `usage` from JSON or the last SSE payload, including the cached prefix each wire reports (`cachedContentTokenCount`, `prompt_tokens_details.cached_tokens`, `cache_read_input_tokens`); usage is published as soon as its bytes are read from the upstream stream (`SseState::capture_usage`), never deferred to the stream end, because a harness may stop reading right after the answer and a cancelled body future would lose the meter. Each payload carries `contextWindow` resolved from the live model catalogue (`api::models::ModelCatalogue`) for the Session's model, so the UI meter follows a refreshed window instead of its own boot snapshot, and `cachedTokens`, the number that says whether compression kept the prefix cached. On non-Google wires `meter::thinking_delta` reads streamed reasoning text, published as `thinking_chunk`; the pi harness therefore drops its own ACP thought chunks (`AcpLaunch::forward_thoughts`) to avoid duplicates.
- `Compressor` trait: `compress`, `decompress`, `search_context`, `status`, `set_policy`, plus `apply`/`apply_skipping` to refold a harness-rebuilt history. A fold is found by its first and last stored turn in order (at most 4 unrelated turns between neighbours), ignoring `thoughtSignature` and `_raw` (the chat wires wrap every turn in a `_raw` copy the proxy's own turns lack), ignoring turns the `SpliceStore` would put back (`SpliceStore::turns`), because the model chose the fold over a history that held steers and proxy pairs the harness never resends, and ignoring turns marked `_nudge`, the transient nudge turn that only the request carrying it ever holds (a fold that spanned one would otherwise never match again). A spliced turn is recognised by its function-call id as well as by equality: a pair changes shape on the wire round trip (name, marker field). Blocks are tried widest first and then repeatedly until nothing moves (a chain of folds over markers takes one round each), so a fold over an earlier fold's raw turns wins and a fold that stored an earlier marker still cascades. `NativeCompressor` swaps a turn range for a summary marker and spills originals to `<session spill>/blocks/<id>.json`; `wire::write_core_contents` strips `_nudge` so no upstream sees it.

## Oversized tool results

`ctx.rs` is the reference's CCR (`kernel/src/ccr.ts`) on our own store. In `prepare_request` every tool result of 4000 estimated tokens or more (the reference's `minToolTokens`; the tools' own 10 KiB spill with a head/tail preview comes first) becomes a deterministic placeholder naming a `ctx:` handle, and the original is written once under `<session spill>/`, where `read ctx:<handle>:<start>-<end>` and `ctx_search` already page it back. The records live in `<session>/ctx.jsonl`. Replace-once: the placeholder is recomputed from the recorded entry, never from fresh bytes, so a harness that resends the raw result gets identical text and the upstream prefix cache stays intact. Both the core part and the `_raw` chat message are rewritten, because `core_to_chat` prefers `_raw`. A `read ctx:` page is never replaced again. Call/result pairing is never touched: only the result's text changes. It runs before the splices and the compressor, because a fold stores the handle and the handle must be back before a later request's fold is matched.

## Nudge gate

`nudge.rs` is the pure ticket-20 gate: `NudgeState::observe_with(tokens, window, compressible, active_blocks, config)` fires the first nudge at `min(75000, window / 2)` once per gate, repeats it whenever the context has grown by `NUDGE_GROWTH_TOKENS` (50000) since the last one, then pressure over `maxContextLimit` and emergency over `emergencyThresholdPercent` on every turn while over, with compressible mass at least `minPressureBenefitTokens` (default `max(5000, window / 100)`). Tier 2/3 fire once when the active block count reaches their trigger and usage is under the pressure band. `reset_after_compress` closes the gate and clears the tier flags. `load` and `save` keep the state in `<session>/nudge.json` (temp file, then rename).

Wiring: `prepare_request` reads a Settings snapshot, applies the compressor policy (`preserveRecentMessages`, `protectedTools`), strips forged markers, runs the preflight backstop when the input alone is over the window, then calls `inject_nudge` on the final contents. Tokens are the last published input usage, or chars / 4 of the turns when none exists; a successful `compress` clears that usage so the next request judges the folded history. The window is the catalogue window; no window means no nudge. The compressible range is turns `1..len-preserveRecentMessages` (start inclusive, end exclusive, as `compress` numbers them), counted at chars / 4. A fired nudge renders `nudge.first`, `nudge.pressure`, `nudge.emergency`, `nudge.tier2` or `nudge.tier3` and is put into the outgoing contents right after the newest tool result. It is transient: no splice stores it, so a later request carries it only when the gate fires again. A turn without a tool result gets no nudge. Injection runs last, on the final contents after the splices, so its turn numbers match what `compress` sees. An emergency nudge also truncates large visible tool results in the outgoing copy only; summaries and the stored history are untouched. `injectTool` and `injectNudge` switch the declarations and nudges off independently; `proxy_compression` is the master switch. The event is `compression` with `action: "nudge"`, `kind`, `tokens`, `sinceLast` and `text`; preflight folds publish `action: "preflight"`, and a request where no stored fold matched publishes `action: "fold-miss"` with `Compressor::fold_report`'s line (the block, where its stored turns started matching, and the first turn that differed). `EMBERLOOP_PROXY_DUMP` writes the stable `<session>.in/.out.json` plus a rotating `<session>.<stage>.<NNN>.json` per request, keeping the newest 60, so two consecutive bodies can be diffed.

`acp_rule` stays out by the ticket decision.

## Tests

`tests/nudge.rs` covers the gate per window size, the band rules, configurable bands, tier triggers, the compress reset, the serde round trip, and replays `parity/golden/` decisions (inject, over-limit, emergency; never reason strings). Golden tests read the files at test time and need no Node.

`src/tests.rs` nudge tests: the first nudge rides the tool-result turn once and replays byte-exact, nothing fires below the threshold, and the gate survives a runtime rebuild through `nudge.json`. It also covers protected tools and the preserved tail, `acp_status` numbers against a golden frame, marker stripping, emergency truncation, preflight folding, and the `injectTool`/`injectNudge` switches. The compress-reset path is covered only by unit tests.
`src/tests.rs` runs a fake upstream and a fake model catalogue. Covers token tamper, prompt/tool injection, usage with its window, byte-exact splice replay after reload, dropped-anchor and double-apply rules, SSE proxy-only continuation, mixed-turn rewriting, the 8-round cap, client disconnect, and round timeout.
