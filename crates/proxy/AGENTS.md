# AGENTS.md — crates/proxy

## Purpose

Model-wire proxy for every harness.
- `router` serves `/health` and `/p/:token/*rest`; `TokenSigner` verifies `hex(session_id).hex(HMAC-SHA256(secret, session_id))`, so a path only reaches the Session it was signed for.
- `handle_generation` and `wire.rs` support Cloud Code (`Google`), OpenAI Chat (`/chat/completions`), Anthropic (`/messages`), and OpenAI Responses (`/responses`) wires: injects pinned policy, Ponytail, caveman and (when `ProxyConfig::codebase_memory` is set, i.e. the daemon found a usable code graph) the `skill.codebase-memory` text into the wire's system field (`systemInstruction`, `messages[0]`, `system`, or `instructions`), appends missing `compress`/`decompress`/`search_context`/`acp_status` declarations to `tools` when `inject_tool` is on, and maps conversation turns through core format so `NativeCompressor`, `SpliceStore`, and Route 1 mid-turn steering work across all wires.
- `x/<provider>/<path>` routes a fixed key or OAuth provider (`emberloop_core::providers::proxy_provider`) to its origin plus `<path>`; the wire comes from the path suffix, the client’s authentication/account headers pass through, an unknown id is 404. `ProxyConfig::with_provider_origin` replaces every origin for tests.
- `claude/<path>` routes the Claude CLI (`ANTHROPIC_BASE_URL=<daemon>/proxy/<token>/claude`) to `ProxyConfig::claude_upstream`. `v1/messages` is the Anthropic wire and runs the same `handle_generation` pipeline as every harness; any other path is forwarded plain with the same bytes. The client's own `authorization`, `x-api-key`, `anthropic-*` and other headers are forwarded in transit only, never stored, logged or published, and the proxy adds no key of its own on this route.
- Codex OAuth uses `/x/openai-codex/backend-api/codex/responses`, routed to `https://chatgpt.com/backend-api/codex/responses` as the Responses wire, never to OpenCode Go. The proxy only forwards the current request’s OAuth/account headers; it does not resolve, persist or refresh subscription credentials. `encoding.rs` bounds zstd decoding by the same 128 MiB generation cap, then `send_stream` re-encodes mutated JSON when the caller sent zstd, preserving correct content encoding and recalculating length. Invalid encoding is 400 and oversized decoded bodies are 413. Plain non-generation forwards retain their original bytes.
- SSE and JSON responses run proxy tool calls (`compress`, `decompress`, `search_context`, `acp_status`) locally and publish `EventKind::Compression` on the `EventBus` when a fold, restore or nudge runs; a pure proxy turn issues a follow-up request into the same client response, a mixed turn keeps only the harness calls and stores the proxy pair as a splice. On the Anthropic wire the pair's model turn is the response's own blocks (thinking with its signature, redacted thinking, text, tool_use), kept as the turn's raw message, and every result shares one user turn. `MAX_TOOL_ROUNDS` is 8, each round has `ProxyConfig::round_timeout` (120 s by default; a test shortens it only when the timeout is its subject), a dropped client body drops the upstream stream, and a send that fails to connect or answers 502/503/504 is retried twice (`ProxyConfig::retry_backoff`, doubling; a test sets it to zero) before the harness sees it. A body cut mid-stream cannot be replayed to the harness, so it ends the stream with an error event on the wire and an `EventKind::Error` on the bus. `validate_range` refuses a fold whose edge cuts a function call from its result (the orphaned half is rejected upstream), naming the id. A follow-up round the upstream answers with a non-2xx status ends the same way, carrying the status and the start of its body.
- `execute_tool` runs `compress`, `decompress`, `search_context` and `acp_status` on the conversation; the harness never sees a proxy call. The `acp_status` report fills the Session's pinned `acp_status.report` template. Every result carries a `📦 [acp] <tool>` marker or a `❌ [acp] <tool>` marker; model-forged marker lines are stripped from outgoing model text and from the `_raw` copy. `marker.rs` is the only place that builds or matches these lines and the summary turn.
- `compress` takes `ranges: [{start, end, summary, topic?}, ...]` (the single `start`/`end`/`summary` form is still parsed). `Compressor::compress_batch(contents, calls, &CompressPolicy)` takes the policy per call and numbers every range against the history as it is now. It validates all of them first (bounds, non-empty summary, preserved recent tail, the latest user message, protected tools; an error names the range), so a bad batch changes nothing. Then, in history order, a range that overlaps an earlier one is skipped: the earlier range folds, and the report carries a `Warning:` line saying the later turns were not folded. Block ids follow history order and folds run from the highest range down. The batch is all-or-none: it stages on a copy, and a spill failure removes the files already written and leaves the history, blocks and next id as they were.
- `SpliceStore` persists to `<data root>/sessions/<id>/splices.jsonl`, append-only, keyed only by the tool-result turn id. `Splice::marker` is the exact string that proves a splice is already applied, so double-apply is impossible; a missing harness anchor drops the splice, a self-anchored proxy pair follows its anchor turn (see Prefix stability). Opaque fields and thought signatures stay byte-exact.
- `meter::extract_usage` reads `usageMetadata`/OpenAI `usage` from JSON or the last SSE payload, including the cached prefix each wire reports (`cachedContentTokenCount`, `prompt_tokens_details.cached_tokens`, `cache_read_input_tokens`); usage is published as soon as its bytes are read from the upstream stream (`SseState::capture_usage`), never deferred to the stream end, because a harness may stop reading right after the answer and a cancelled body future would lose the meter. Each payload carries `contextWindow` resolved from the live model catalogue (`api::models::ModelCatalogue`) for the Session's model, so the UI meter follows a refreshed window instead of its own boot snapshot, and `cachedTokens`, the number that says whether compression kept the prefix cached. `inputTokens` is the whole prompt: on Anthropic it is `input_tokens` plus cache reads and writes, because the provider's `input_tokens` leaves those out; `cacheCreationTokens` is Anthropic's top-level `cache_creation_input_tokens` (the nested `cache_creation` split sums to it, so it is not read); OpenAI totals (Chat and Responses) already include their cached part; Gemini's `promptTokenCount` includes explicit `cachedContentTokenCount`, while the implicit-caching inclusion is inferred, not verified. On non-Google wires `meter::thinking_delta` reads streamed reasoning text, published as `thinking_chunk`; the pi harness therefore drops its own ACP thought chunks (`AcpLaunch::forward_thoughts`) to avoid duplicates.
- `Compressor` trait: `compress_batch`, `decompress`, `search_context`, `status`, `fold_report`, plus `apply_skipping` to refold a harness-rebuilt history. A fold is found by its stored turns in order (at most 4 unrelated turns between neighbours), compared as `turnkeys::same_turn` (see Turn keys). Only the matched turns are replaced, by the summary turn where the first one stood; unrelated turns between them stay in the request, except transient nudge turns and turns the `SpliceStore` would put back (`SpliceStore::turns`, passed as `skip` to `apply_skipping`), which are dropped with the fold. A spliced turn is recognised by its function-call id as well as by equality: a pair changes shape on the wire round trip (name, marker field). Blocks are tried widest first and then repeatedly until nothing moves (a chain of folds over markers takes one round each), so a fold over an earlier fold's raw turns wins and a fold that stored an earlier marker still cascades. A block whose summary turn is already in the history is skipped, so each block applies at most once and a refold of its own result changes nothing. Among the spans that match its stored turns, a fold takes the one nearest its stored start (`Block::start`, the index it was made at), moved by the turns removed by folds applied earlier in the same pass; repeated turns therefore fold where the fold was made, not at their first occurrence. `NativeCompressor` swaps a turn range for a summary marker and spills originals to `<session spill>/blocks/<id>.json`; `wire::write_core_contents` strips the nudge mark so no upstream sees it.
- `NativeCompressor::new` reloads `blocks/*.json`, including exact summary turns and restored flags, and advances block ids beyond the largest stored id. Malformed or unreadable block files fail runtime creation rather than being overwritten. A block file without its `summaryTurn` fails runtime creation the same way; no older format is read. Writes use a temporary file and rename; they do not guarantee power-loss durability.
- `reset_history` archives the block directory as `blocks-reset-N` (`NativeCompressor::archive_blocks`) before starting an empty compressor for a new harness conversation. Archived originals remain on disk. Compressor originals and touched Session runtimes still remain in RAM; spilling is not a memory eviction policy.
- A reset keeps the conversation: `prepare_request` stores the core turns the model last saw (`last_history`); `reset_history` runs them through `carry::sanitize` (drops `_raw`, `opaque` parts such as thinking and signatures, empty turns; merges same-role neighbours) into `carried`, and every later request starts with them (`carry::join` merges the seam). This is how a harness or model switch keeps its history on any wire. Limits: the last answer is not in the request, so it is missing; `carried` is in memory only; the prompt cache is lost once.

`search_context` returns a `SearchReport`; the tool text is `SearchReport::render`. Each block's topic and summary are scored first, then the original turns of blocks whose summary was not shown (`original_text`: message text, call names and arguments, tool-result strings; fold marker lines dropped). Visible messages are never searched. Query words are split on whitespace and lowercased, a text scores the sum of its words' occurrence counts, only positive scores count, and ties keep history order. `limit` (default 5, at least 1) caps the summary hits and the original-text hits separately; the report keeps the summary candidate count for the truncation note. Restored blocks stay searchable with `inactive` set. A snippet is 200 characters from 80 before the rarest matched word, which is marked 【】. A query of three or more words gets a tip naming a word that no shown block contains but a lower-ranked one does.

## Context breakdown

`context.rs` classifies the final outgoing request on all four wires (including Google's `request` wrapper). Each response usage event carries `breakdown`: `system`, `toolDefinitions`, `toolCalls`, `toolResults`, `compression`, `conversation`, `images`, `imageCount`, `estimatedTokens`. Estimates use the token rule in `tokens.rs` (below): message text, tool-result strings and keys count by their text, tool definitions and tool calls by their serialised JSON. Image payloads are excluded, counted as images only (`images` stays zero), and no category is claimed to be exact or forced to equal provider input usage. Compression is retained native summary text, not folded originals. Buffered continuations use their final request; streaming continuations clear per-request usage deduplication even when provider counts happen to match. Only aggregate counts, not prompt or image contents, reach the UI. Generation bodies are capped at 128 MiB so five maximum-size base64 image attachments plus conversation overhead fit. `tests/context.rs` covers classification and media exclusion; fake-upstream tests cover injection, compression, large image bodies and Codex’s zstd request / nested `response.completed` usage / mid-turn steer path, plus a streamed proxy-only compression call whose recompressed follow-up carries folded context and a lower provider-reported input count.

## Token estimate

`tokens.rs` is the one estimate. Per text it is the billion-context reference rule (`defaultCountTokens`): each CJK character counts one token and the other characters `ceil(n / 4)`, over characters, not bytes. A turn is the sum of its texts: message text, a call's name and arguments, and every string in a result's response. Nudge timing (the fallback when no usage is published, and the compressible range), preflight folds, the compressed-tokens total, the oversized-result threshold in `ctx.rs` and the context breakdown all read it.

## Oversized tool results

`ctx.rs` is the reference's CCR (`kernel/src/ccr.ts`) on our own store. In `prepare_request` every tool result of 4000 estimated tokens or more (the reference's `minToolTokens`; the tools' own 10 KiB spill with a head/tail preview comes first) becomes a deterministic placeholder naming a `ctx:` handle, and the original is written once under `<session spill>/`, where `read ctx:<handle>:<start>-<end>` and `ctx_search` already page it back. The records live in `<session>/ctx.jsonl`. Replace-once: the placeholder is recomputed from the recorded entry, never from fresh bytes, so a harness that resends the raw result gets identical text and the upstream prefix cache stays intact. Both the core part and the `_raw` chat message are rewritten, because `core_to_chat` prefers `_raw`. A `read ctx:` page is never replaced again. Call/result pairing is never touched: only the result's text changes. It runs before the splices and the compressor, because a fold stores the handle and the handle must be back before a later request's fold is matched.

## Prefix stability

The provider's prompt cache hits only when a request starts with the bytes of the previous one. The harness resends its whole history, so the proxy rebuilds the same bytes for every turn it already sent.
- Fixed per process: the system prompt and the tool declarations (`PinnedPrompts`).
- Changes an earlier turn once, then keeps it: a `ctx` handle replacing an oversized result on arrival, the first emergency truncation, a `compress` or preflight fold from its start turn on, and `reset_history`. No other path may change an earlier turn.
- Transient, never in the prefix: the nudge sits after the newest tool result and `write_core_contents` strips its mark.
- Emergency truncation is sticky. An emergency nudge sets `SessionRuntime::emergency_truncated`; every later request then truncates its older results on the outgoing copy with the same rule, until a `compress`, a preflight fold or `reset_history` clears it. `outgoing_body` makes that copy at send time; the stored request keeps every full result, so a `compress` or `decompress` in the emergency request stores and restores the full text. The band is judged on the usage of the truncated body, so without the flag the emergency flips on and off. The flag is in memory only: a restarted proxy starts clear and may flip once.
- Splice anchor: a self-anchored proxy pair (`compress`, `decompress`, `search_context`, `acp_status`) records `Splice::after_turn` when it is created, the `turn_key` of the newest non-transient turn of the request: `call:<id>` for a tool result, `text:<sha256>` for a text-only user turn, none for a model turn. On apply it goes right after the first turn with that key, so its index stays fixed as the history grows. A key only ever matches a user turn, so the wire order holds by construction.
- Fallback: when the anchor turn is gone (folded away, rewritten), the pair goes right after the nearest user turn before the newest model turn (directly before that model turn in an alternating history, as before). That user turn becomes its `after_turn`, appended to `splices.jsonl` (a later line with the same id replaces the earlier one). A model turn is never a key, so a model-after-model placement cannot be recorded. A record without the field loads with no anchor and takes the same path.

## Nudge gate

`nudge.rs` is the pure ticket-20 gate: `NudgeState::observe_with(tokens, window, compressible, active_blocks, config)` fires the first nudge at `min(75000, window / 2)` once per gate. Pressure over `maxContextLimit` and emergency over `emergencyThresholdPercent` fire on every turn while over, ahead of the first nudge, with compressible mass at least `minPressureBenefitTokens` (default `max(5000, window / 100)`). After a nudge, another repeats whenever the context has grown by `NUDGE_GROWTH_TOKENS` (50000) since the last one; the reference falls to the current count when the context shrinks. Tier 2/3 fire once when the active block count reaches their trigger and usage is under the pressure band. `reset_after_compress` clears the tier flags and leaves the gate shut, so a fold paces the next one by the same growth step: a fold rewrites the provider cache from turn 1, and a reopened gate folded on every step. `load` and `save` keep the state in `<session>/nudge.json` (temp file, then rename).

Wiring: `prepare_request` reads a Settings snapshot, passes the compressor policy (`preserveRecentMessages`, `protectedTools`) to each fold, strips forged markers, runs the preflight backstop (folds, one run at a time, the first `compressor::foldable_runs` run of more than one turn inside `1..` up to the preserved tail, never reaching the latest user message; the same `compressible_end` helper as the nudge range, so a latest user message at turn 0 cuts nothing; it stops when no such run is left) when the input alone is over the window, then calls `inject_nudge` on the final contents. Tokens are the last published input usage, or the token rule over the turns when none exists; a successful `compress` clears that usage so the next request judges the folded history. The window is the catalogue window; no window means no nudge. The compressible range is turns `1..min(len-preserveRecentMessages, latest user message)` (start inclusive, end exclusive, as `compress` numbers them; the latest user message is never in it, as `compress` refuses it, and a latest message at turn 0 cuts nothing). Its foldable runs are counted by the same rule, and the ranges text lists each run as `turns a–b`; protected turns inside the range are skipped. A fired nudge renders `nudge.first`, `nudge.pressure`, `nudge.emergency`, `nudge.tier2` or `nudge.tier3` and is put into the outgoing contents right after the newest tool result. It is transient: no splice stores it, so a later request carries it only when the gate fires again. A turn without a tool result gets no nudge. The gate is observed on a copy and committed (`SessionRuntime::commit_nudge`, saved to `nudge.json`) only when upstream answers with a success status; a failed, cancelled or refused request leaves it open, so the model still gets the nudge on the retry. Injection runs last, on the final contents after the splices, so its turn numbers match what `compress` sees. An emergency nudge also sets the sticky truncation of large visible tool results (see Prefix stability); summaries and the stored history are untouched. `injectTool` and `injectNudge` switch the declarations and nudges off independently; `proxy_compression` is the master switch. The event is `compression` with `action: "nudge"`, `kind`, `tokens`, `sinceLast` and `text`; preflight folds publish `action: "preflight"`, and a request where no stored fold matched publishes `action: "fold-miss"` with `Compressor::fold_report`'s line (the block, where its stored turns started matching, and the first turn that differed). `EMBERLOOP_PROXY_DUMP` writes the stable `<session>.in/.out.json` plus a rotating `<session>.<stage>.<NNN>.json` per request, keeping the newest 60, so two consecutive bodies can be diffed.

Skill catalog: `SessionRuntime::new` reads `<session>/skill-catalog.md` once into `catalog` (empty when the file is absent). `prompt_text(pins, codebase_memory, catalog)` appends it after the codebase-memory part, so it lands in the top-level system field of all four wires, and `inject_prompts_for_wire` takes the same argument. The daemon writes the file once per Session before the harness spawns and never edits it, and the runtime never re-reads it, so the system prompt is byte-stable for the Session. `src/tests.rs` checks that a rewritten file leaves the rendered text unchanged.

`acp_rule` stays out by the ticket decision.

## Turn keys

`turnkeys.rs` is the only owner of the keys a turn carries beside its content: the nudge mark, the chat wires' `_raw` copy and the Google `thoughtSignature`, and the `emberloop-splice:` marker prefix. Comparison uses the canonical view with `_raw` and `thoughtSignature` dropped at any depth; the nudge mark is not dropped, so a nudge never equals a plain turn. Stored originals keep all of these keys, because decompress restores them; nothing strips them from a stored turn. The compressor's source names none of the keys (a guard test in `turnkeys.rs` enforces it).

## Protected content

`protect.rs` owns the one notion of protected content: a system or developer item on any wire, and a user turn with a text part that contains `<system-reminder>` (Claude Code's CLAUDE.md, environment and skill text). Protected content never folds, is never replaced by a marker, and is never counted as foldable.
- System and developer items are not core turns. `extract_core_contents` skips them on every wire, and `write_core_contents` writes the request's own items back first, in their original order, byte for byte. The top-level `system`, `systemInstruction` and `instructions` fields are not turns; the proxy's policy text goes only there.
- A protected user turn is protected whole, so a message mixing a reminder with the user's own text does not fold either. `validate_range` refuses any range covering one, naming it and saying it never folds; a stored fold never matches across one (`find_span`); and nudge and preflight count and fold only `compressor::foldable_runs`, the runs of foldable turns from turn 1.
- Text inside a tool result never makes a turn protected. Arrival replacement, marker stripping (model turns only) and emergency truncation (tool results only) touch no protected text.

## Tests

`tests/nudge.rs` covers the gate per window size, the band rules, configurable bands, tier triggers, the compress reset, the serde round trip, and replays `parity/golden/` decisions (inject, over-limit, emergency; never reason strings). The silent-frame test allows exactly the first-threshold frames in `KNOWN_EARLY` and pins each golden's first-fire counts in `FIRST_FIRES`; any other drift fails. Golden tests read the files at test time and need no Node.

`tests/compressor_characterization.rs` pins the `Compressor` through its public API (turn matching, refold and skip, `fold_report`, summary marker, token estimate, policy, batch validation) against `tests/fixtures/compressor/`.

`tests/compressor_properties.rs` (proptest, 64 cases, no persistence) generates 2 to 29 turn histories and checks through the public API: refolding the harness view reproduces the fold and a second pass changes nothing, fold then decompress restores the turns exactly, and a failed batch leaves history, status and spill files unchanged. Its repeated-text refold property runs with the same checks, and `compressor_characterization.rs` pins the repeated-turn cases (the minimal `[ok, ok, final]` and a two-fold batch whose second start shifts).

`turnkeys.rs` unit tests pin the canonical view, the nudge mark and the splice marker.

`tests/protected_system.rs` runs each wire through the protected-content contract (table cases, the policy text, a decompress) and a proptest of random splice requests that checks every protected item's bytes survive. `protect.rs` unit tests pin `is_protected`.

`src/tests.rs` prefix-stability tests drive a growing Session through the fake upstream; each request must open with the previous one, except its nudge turn, its newest turn and the breaks in the table in that file's doc comment. They cover steady growth, the first nudge, a mid-run compress (the proxy pair keeps its index), a reset and the emergency flip-back, and the flag clearing on a compress and on a preflight fold. `splice.rs` unit tests pin the anchor: the same index over five requests, the fallback and its re-recorded anchor across a restart, a model turn never as an anchor, and old records without the field. `src/tests.rs` protected-content tests run the nudge, preflight and an all-protected request through the Claude and pi Anthropic routes. `src/tests.rs` nudge tests: the first nudge rides the tool-result turn once and replays byte-exact, nothing fires below the threshold, and the gate survives a runtime rebuild through `nudge.json`. A failed (500) or cancelled upstream request leaves the first nudge for the retry. It also covers protected tools and the preserved tail, `acp_status` numbers against a golden frame, marker stripping, emergency truncation, preflight folding, and the `injectTool`/`injectNudge` switches. The compress-reset path is covered only by unit tests.
`src/tests.rs` runs a fake upstream and a fake model catalogue. Covers token tamper, prompt/tool injection, usage with its window, byte-exact splice replay after reload, dropped-anchor and double-apply rules, SSE proxy-only continuation, mixed-turn rewriting, the 8-round cap, client disconnect, and round timeout.

## Background skill review

`review.rs` holds the rules; `SseState::review_check` and `run_review` in `server.rs` run it. `SessionRuntime.review` counts in memory: +1 per round that forwards a harness call, reset to 0 by a `skill_manage` call. A round that forwards nothing is a final answer; it starts a review when `Settings.skills_review_interval` is above 0, the count reached it, no review runs, the request's tools offer `skill_manage`, and `ProxyConfig.review_tools` is set. The fork is the last outgoing body plus one user message with the `review.skills` prompt, with `stream` false (Google: `:generateContent`, `alt=sse` removed; unverified against cloudcode). The nudge turn the main request carried (found by its rendered text in `SseState.nudge_text`) is dropped from the fork, since it speaks to the main conversation; the fork never injects a nudge, touches the nudge gate or publishes usage. It runs up to 16 rounds, each tool call through the injected `ReviewTools` executor. The client's auth headers live only in the spawned task. Nothing enters the Session history; each round's usage goes to `<session>/review.jsonl`, and one `compression` event with action `skill-review` is published only when a `skill_manage` call succeeded. A restart resets the count.

`review.rs` unit tests pin the counter, the per-wire fork body and the call and result shapes. `src/tests.rs` runs the fork against the fake upstream: the prefix and `tools` stay identical, `stream` is false, results and the denial reach the model, a request without `skill_manage` never starts a review, and a nudge the main request carried is absent from the fork.
