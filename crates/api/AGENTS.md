# AGENTS.md — crates/api

## Reviewer subagents

`subagents.rs` owns `POST /api/sessions/{id}/subagents` and `subagent_recovery.rs` owns the fallback ladder recovery engine (`SubagentRun` in process-local `AppState::subagent_runs`, pruned on session deletion, not persisted across daemon restarts; terminal exhaustion ignores trailing `EventKind::Error` events, and `reconfigure_for_rung` retries once on `409 Conflict` when `!is_turn_active()` after dead-handle eviction): reviewer (`spec`/`standards`) singleton reuse, parallel `worker` and `scout` child Sessions (fresh per `spawn`, reused on `steer`), 1-level enforcement blocking any subagent from calling `spawn`/`steer`/`stop`/`result`, assignment validation, ownership checks, dispatch, ordered `FallbackLadder` execution (`retry_backoff` 2s/5s, max 2 transient retries per rung resetting on recovery, immediate escalation on hard errors, clearing `resume_token` on cross-harness `source` changes, replaying the initial task prompt when no assistant/tool/idle progress occurred or sending a continuation prompt otherwise), and per-submission delivery. `worker` and `scout` accept optional `tier` (`smol`, `mid`, `top`; `spawn` defaults to `mid`, sets default title `"Worker (<tier>)"` / `"Scout (<tier>)"`, returns `{ id, role, tier }`; `steer` with `tier` switches model/effort while idle or returns `409 Conflict` when active, persists `ReviewerAssignment.tier`, and updates auto-generated `"Worker (<tier>)"` / `"Scout (<tier>)"` titles); `spec` and `standards` reject `tier`. `result` reads report history from the parent queue. Only `submit` forwards reports; terminal subagent errors (after ladder exhaustion) and manual cancellation notify the parent separately, while `mark_cancelled` suppresses retries/escalation on manual `stop`. Recovery restores queued delivery, not subagent work. Settings validate and persist `FallbackLadder` (`Vec<ModelRung>`) arrays (supporting legacy single-object deserialization) for `spec_reviewer`, `standards_reviewer`, and `subagent_tiers` (`smol`, `mid`, `top`; fresh settings default all three tiers to a single `default_model` rung) against the model catalogue, rejecting empty ladders with `400`. `goldfish_tiers` (`smol`, `mid`, `top`) is validated the same way, except every ladder defaults empty and an empty ladder is accepted: a goldfish walks its own ladder when set and the matching `subagent_tiers` ladder when empty, so only non-empty goldfish ladders are checked. A `notice` with `action: subagent_created` refreshes the sidebar.
`spawn` accepts an optional `batch` name: trimmed, 1 to 64 characters, no ASCII
control characters, else `400`. `handle_spawn` pre-registers the child under
`state.subagent_gate` before dispatch; the batch seals when the parent turn ends,
and appending to a sealed batch or reusing a `spec`/`standards` reviewer already
pending in one is `409`. A batched member's report stays `Held`: `submit` replies
`heldInBatch: <batch name>` and publishes no `SteerQueued`, while `result` still reads it.
A sealed batch whose pending members reach zero releases every held report behind
one notice, one event each, and one wake. A delegate whose registration fails is
deleted instead of left idle.
`recover` scans every Session, not only reviewer parents: it calls
`reconcile_on_startup`, republishes missing `SteerQueued` events only for
non-`Held` entries, and wakes an idle parent once so a pre-restart batch
releases immediately instead of waiting for the deadline.

`subagent_submit.rs` enforces the report rule: `begin_turn` opens one obligation per subagent turn (spawn, steer and review; a recovery prompt keeps it), `record_submit` clears it only after the report is delivered, and `watch_submits` nudges an idle turn without one up to three times (`NUDGE_PROMPT`), then files a `blocked` report to the parent carrying the finished turn's own assistant text, so the parent is never left silent. A refused submit leaves the turn open; a non-subagent Session has no obligation.
`session_setup.rs` validates creation defaults before a reviewer is saved. It configures the driver only for an existing Session; a new Session starts its harness with the saved model on its first prompt. Session timestamps use milliseconds, matching ordinary Session creation.

`spawn role=goldfish` (goldfish design, `docs/superpowers/specs/2026-11-16-goldfish-design.md`) starts a fresh, stateless, one-shot reviewer: `persona` is required (other roles reject it), `text` is required, `title` defaults to `Goldfish (<persona>)`, `tier` defaults to `mid`. `personas.rs` resolves the persona (`api::personas::resolve_persona`, wrapping `tools::personas`) and an unknown id is `400` naming it and listing the available ids; the id is stored on `ReviewerAssignment.persona` so recovery and the proxy re-send it. The fallback ladder, recovery, nudges and the 1-level rule treat it like `scout`. One-shot: `subagents` `steer` and the HTTP `/api/sessions/{id}/prompt` and `/steer` handlers answer `400` for the goldfish role (`routes::ensure_not_one_shot`); internal callers (`prompt_child_raw`, recovery, nudges) use the unguarded `prompt_session_inner`/`steer_session_inner`. Auto-stop: `subagent_submit::enforce` stops a goldfish through `routes::stop_session(.., notify=false)` when its turn goes idle after an accepted `submit`; the stop sends no `stopped` report, keeps the transcript, and `mark_cancelled` makes the run terminal so recovery cannot resurrect it. A goldfish that ends without a report still gets the nudges and a `blocked` report, and is not auto-stopped.

## Purpose

Exposes axum REST API, SSE event endpoints and the model catalogue with utoipa OpenAPI schema generator:
- `/api/projects`: list, create, update, delete projects
- `/api/projects/clone`: add a Project by `git clone`. `project_clone.rs` takes the folder name from the repository URL, expands `~` with `$HOME`, refuses an existing folder, and runs `git clone --` with `GIT_TERMINAL_PROMPT=0`, a 120-second timeout and no stdin, so a private clone fails on the local git credentials instead of hanging on a prompt.
- `/api/projects/:id/design` returns the private edit link for the project’s one live FigCraft document, or 503 when unavailable. `design.rs` keeps a project MCP client for atomic five-second `design.figcraft` snapshots. `/api/figcraft/live/` proxies WebSocket frames only to the loopback FigCraft server and rejects cross-origin or missing-Origin requests. FigCraft normalizes the server path with a trailing slash and sends file credentials in its binary Hello, not WebSocket query parameters. The publish key stays server-side.
- `/api/sessions`: list, create, update, delete sessions. PATCH accepts `model` and `thoughtLevel` together; `session_setup.rs` validates catalogue efforts and idle state, waits for the driver acknowledgment, then persists settings. Unknown models/efforts are 400; busy/refused changes are 409 and keep metadata unchanged.
- `/api/sessions/:id/prompt`: user prompt with text and images; refreshes `lastUsedAt`. The prompt route allows 70 MiB JSON bodies for up to five 10 MiB PNG/JPEG/WebP/GIF attachments and rejects known text-only models. While the Session's turn is active a prompt, with or without images, is queued as a steer instead, so a reloaded UI that thinks the Session is idle cannot hand the harness a second prompt.
- `/api/sessions/:id/usage`: prompt-cache history, one `UsageRecord` per request from the Session's `usage` events, oldest first; `?limit=` keeps the newest N (default 200, max 1000). `inputTokens` is the whole prompt, `freshInputTokens` the uncached part (`input - cached - creation`), `hitPercent` is `cached / prompt * 100`, null for an empty prompt, and `fold` marks the request a `compress` landed before, so the page can attribute a hit dip to the fold instead of the provider. Built in `src/usage.rs` from `EventLog::kind_tail`: the newest usage events, joined with the newest `compression` events it reads for the fold positions.
- `/api/sessions/:id/file?path=`: read-only file for the feed (`src/files.rs`). `path` is absolute, relative to the Project root, or a `file://` URL; it is canonicalised and must lie inside the Session's Project root or its Session directory, else 404. Files over 10 MiB answer 413. Content type comes from the extension (images, HTML, PDF; JSON, Markdown, logs and source as `text/plain`; the rest `application/octet-stream`), and every response carries `nosniff` and `Content-Security-Policy: sandbox` so served HTML or SVG runs no script.
- `/api/sessions/:id/steer`: steer input queue, `{text, images}` with the same image limits as the prompt; the proxy injects it on the next request while a turn runs, otherwise the Session is woken with it (every harness alike, images included)
- `/api/sessions/:id/cancel`: cancel current execution
- `/api/sessions/:id/events`: SSE event stream with `?after=<seq>` replay. A first load (`?limit=N`, no cursor) sends the tail window, then one named `snapshot` frame (`{status, usage, todos}`: the newest status, usage (including the proxy breakdown) and todo-list event data, however old), so a long working Session does not open as idle and its plan card survives a reload. The frame has no seq and never appears in history pages.
- `/api/personas?project=<id>`: read-only list of `{name, description, path}` for the goldfish personas found for the Project, read from disk on every call (no cache). Search order, first match wins: `<project root>/.agents/agents/*.md`; `agents/*.md` in each skill folder under the Project skill root; `agents/*.md` beside the global skills root; `agents/*.md` in each skill folder under the global skills root. The id is the frontmatter `name`; other keys are ignored and a file with bad frontmatter is skipped with a `tracing::warn!`. Outside `openapi.json`, like `/api/skills`.
- `/api/skills?project=<id>&q=<text>&limit=<n>`: skill summaries, global and (with `project`) that Project's, hidden skills included, outside `openapi.json`. Without `q` it lists every skill and ignores `limit`. With `q` (`src/skills.rs` `ranked`) it answers name-prefix matches first, alphabetical and case-insensitive, then other skills by `tools::skillsearch::score`, the same BM25 the `skill_search` tool uses, highest first; `limit` defaults to 20 and caps at 50.
- `/api/status/sessions/events`: SSE stream of every Session's status (`src/sse.rs`). Each connection seeds one named `status` frame per Session (`{sessionId, status}`, the newest `status` event's data), then follows every live `status` event. The sidebar marks Sessions this page never opened, so it cannot read their status from one Session's log.
- `/api/status/binaries?refresh=false|true`: `200` with `{checkedAtMs, binaries:[{id, name, path, installedVersion, latestVersion, state, error}]}` (`state` is `upToDate`, `outdated`, `missing` or `error`) from the daemon's `BinaryChecker`, or `503` when `AppState::binaries` is `None`. The DTOs `BinariesStatusDto`, `ExternalBinaryDto` and `ExternalBinaryState` live in `src/status.rs` and are in `openapi.json`. `refresh=true` re-probes versions older than the checker's 30 s floor; a plain call answers from the cached probe. `AppState::with_binaries` installs the checker.
- `/api/tool-keys`: `GET` lists `brave`, `exa` and `jina` with the shell variable each sets and whether it is set (never the value); `PUT /api/tool-keys/{name}` with `{ value }` stores or, on an empty value, clears that key in `<config root>/tool-keys.json` (`store::tool_keys`, 0600); the tools read that file on every call, so no environment variable and no restart are involved. Unknown names are 404; a daemon without a config root answers 409.
- `/api/settings`: get and update system settings, including the ticket-20 Context keys (`max_context_limit`, `min_pressure_benefit_tokens`, `emergency_threshold_percent`, `preserve_recent_messages`, `protected_tools`, `inject_tool`, `inject_nudge`, `tier2_trigger`, `tier3_trigger`); `serde(default)` fills them for older saved settings.
- `/api/prompts`: list prompt ids with default/override/active hashes; `PUT/DELETE /api/prompts/:id` writes or removes an override
- `/api/models`: merged model catalogue; `POST /api/models/refresh` forces the configured sources to refresh
- `/api/providers`: list providers, Antigravity login flow, and `PUT`/`DELETE /api/providers/:id/key` for API-key providers (`opencode-go` and the `emberloop_core::providers` registry; any other id is 404). `ProviderView.auth` is `login` or `key`
- `/api/version`: reports `EMBERLOOP_BUILD_VERSION` when supplied at build time, otherwise the crate version, matching the daemon release version.
- `/api/push/key` (`GET`) and `/api/push/subscribe`, `/unsubscribe`, `/visible`, `/test` (`POST`): Web Push, outside `openapi.json` like `/api/transcribe`. `push.rs` owns the VAPID keypair (`<data root>/push-vapid.json`, generated on first load), the per-browser subscriptions (`<data root>/push-subscriptions.json`) and the visibility stamps; `AppState` carries one `Push` built from the data root. The free function `push::watch(AppState)` follows the `EventBus` and pushes `{title, body, url}` — the Session title and `/p/<project>/s/<session>` — for a `status` with `state: idle` or an `error`, but only when no page reported that Session within `GRACE` (30 s). The page heartbeats `/visible` every 20 s while it shows the Session, so exactly one of the in-app notice and the push fires. A 404/410 from the push service drops that subscription. Sending builds the request with `web-push` (`default-features = false`) and posts it through the crate's own `reqwest` client, so no second HTTP client enters the tree.
- `/openapi.json`: OpenAPI 3.0 specification
- `AppState::new` reads prompts from `<data root>/prompts`; `AppState::with_prompts` and `AppState::with_models` let the daemon pass the config-root prompt store and multi-source model catalogue.

## Model catalogue

`src/models.rs` owns `ModelEntry`, the async `Source` trait and `ModelCatalogue`. Sources merge by `id` in source order. A failing source keeps its last good entries, marked `stale`, and records the error. The daemon supplies every source, including the dynamic agy one; `AppState::with_prompts` starts with no sources and `with_models` replaces them. The snapshot is `<data root>/models/catalogue.json`, written by temp file and rename and loaded before the first refresh. The daemon calls `spawn_refresher` at boot; it refreshes immediately and every 10 minutes. The catalogue is in `AppState::models`, and `ModelCatalogue::window` answers a model's context window for the proxy's usage meter.

## Title and usage contracts

Settings include `title_generation` (default true) and `title_model` (default `openrouter/openrouter/free`). PUT validates the provider/model format, then writes the whole Settings to `settings.json` under the data root and only then swaps the in-memory copy, so reviewer model defaults and every other choice survive a daemon restart or update; a failed write is a 500 and leaves the running settings untouched. `GET /api/providers/{provider}/usage?refresh=true` calls the daemon usage seam and returns `UsageView { windows, balance, error }`; percentages describe used quota, resets are epoch-second strings or provider timestamps. No credentials are returned. PATCH applies explicit title changes through `SessionsStore::update_title`.
